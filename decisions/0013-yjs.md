# Hold the editable document in Yjs, behind a subpath export of `core`

## Context

The editor edits one document that will be shared between the browser, the server and later several users. Edits must be undoable one command at a time, and replicas must converge. The command reducers in `core` are pure and framework-free; units shared with other hosts need them without any CRDT.

## Considered options

- Yjs 13.6: pure JavaScript CRDT with `Y.Map`, `Y.Array`, an `UndoManager` scoped by transaction origin, and a Python peer (pycrdt) for the server.
- Automerge: no undo API; WebAssembly core of about a megabyte; Python bindings not stable.
- Loro: thin Python binding, no provider ecosystem; WebAssembly core.
- Write it ourselves: an operation log with undo is feasible for one user, but convergence across replicas is a CRDT research problem.

## Decision

Use Yjs 13.6.33, imported only by `app/packages/core/src/yjs/`, published as the subpath export `@timetoalign/tilie-core/yjs`. The root export of `core` never imports Yjs; dependency-cruiser enforces it (`yjs-only-in-core-yjs-entry`, `core-root-export-without-yjs`). Yjs is an optional peer dependency of `core` (range `^13.6.33`; its tests use an exact development dependency, and the lockfile pins 13.6.33), so a host that uses only the reducers installs no CRDT.

Every coordinate dict, map payload, region, break and jump entry, `meta`, `measure_map` and `metric_hierarchy` is one atomic value, stored as one Yjs string: its compact JSON text (`compactJson` of `@timetoalign/timeskeleton`, read back with its `parseJson`). Yjs would otherwise turn an integral float (a `JsonFloat`) into a plain object and wrap integers at 2^63; the text keeps every number and the order of every member. Ordering of collections is derived when the document is materialized. Breaks and jumps are held in `Y.Map`s keyed by a per-replica insertion key rather than in `Y.Array`s: in Yjs 13.6.33, once the creation of an array's parent has been undone and redone, redoing the deletion of one array entry also deletes the entry inserted after it (adjacent items are merged and the redo deletes the merged item whole). `Y.Map` entries are never merged. The property tests found this; a fixed regression test pins it.

A standalone reproduction (Node, Yjs 13.6.33 alone, saved as `repro.mjs` next to an installed `yjs`):

```js
import * as Y from "yjs";

const doc = new Y.Doc();
const root = doc.getMap("root");
const origin = Symbol("local");
const undo = new Y.UndoManager(root, { trackedOrigins: new Set([origin]), captureTimeout: 0 });
const list = () => root.get("parent").get("list");

doc.transact(() => {
  const parent = new Y.Map();
  parent.set("list", new Y.Array());
  root.set("parent", parent);
}, origin);
doc.transact(() => list().push(["a"]), origin);
doc.transact(() => list().push(["b"]), origin);
doc.transact(() => list().push(["c"]), origin);
doc.transact(() => list().delete(1, 1), origin); // remove "b"

const steps = undo.undoStack.length; // 5
for (let i = 0; i < steps; i += 1) undo.undo();
const seen = [];
for (let i = 0; i < steps; i += 1) {
  undo.redo();
  seen.push(root.get("parent") ? JSON.stringify(list().toArray()) : "none");
}
console.log(seen.join(" | "));
// expected: [] | ["a"] | ["a","b"] | ["a","b","c"] | ["a","c"]
// actual:   [] | ["a"] | ["a","b"] | ["a","b","c"] | ["a"]
```

The same sequence on a `Y.Array` created outside the undone transaction, or on a `Y.Map` keyed per entry, redoes correctly.

## Maintenance and dependencies

Yjs 13.6.33 (released 2026-09-23, MIT, 2,308,376 bytes unpacked including sources and type declarations) is maintained by Kevin Jahns with a broad contributor base and corporate users; releases are frequent patch releases on the 13.6 line while 14 is in pre-release. Its one dependency is lib0 (0.2.118 resolved, released 2026-09-25, MIT, same maintainer). The bus factor is low at the maintainer level and mitigated by the size of the user base and the Rust port (Yrs) that pycrdt builds on.

Primary sources: <https://registry.npmjs.org/yjs>, <https://github.com/yjs/yjs>, <https://docs.yjs.dev/api/undo-manager>, <https://registry.npmjs.org/lib0>.

## Consequences

The reducers stay the only place where invariants are checked; Yjs is one applier of them. Concurrent edits merged by Yjs bypass the reducers and may break an invariant; loading and saving validate the merged document. Exit cost: the binding is one file over a materialize-and-diff interface; replacing Yjs means rewriting that file and the provider, not the reducers.
