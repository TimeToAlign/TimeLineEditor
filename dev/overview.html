TimeLineEditor (TiLiE)#

TiLiE is a local browser editor and visualization tool for musical timelines represented by the Python timetoalign library. It edits a workspace, a canvas of blocks. A block places one manifest on the canvas: a TimeToShare manifest of the one shape every manifest has, holding root timelines (each with exact coordinates, child offsets, conversion maps, regions and flow control), optionally grouped into timeline groups, beside the measure maps its conversion maps read, and the statements that say what the manifest, its timelines and its regions stand for: works, recordings, editions, the people involved. A manifest knows nothing about where it is shown.

Status: alpha. The editor described below is in the source tree. The tilie-server release on PyPI predates it and serves only the application shell: it installs, serves the bundled editor on 127.0.0.1 with a fresh token for each run, and reports its health.

What works in the source tree:

  • Manifests and workspaces (core). Manifests of TimeToShare schema 0.2.0, the current version, with exact numbers:

    • validated load of any manifest in YAML or JSON, completed with every default it leaves out, and save in the complete or the minimal form, with or without its styling, in canonical YAML, pretty JSON or RFC 8785 JSON;

    • unknown keys kept and written back, and timelines of unknown length;

    • the statements of TimeToShare’s description specification, property–value pairs with their provenance, on the manifest, its timelines and its regions, each element’s set as a whole; a held manifest keeps of its JSON-LD @context only the prefixes it declares itself, and every file it is written to carries the full context;

    • element addresses, and the workspace view with its blocks, ids and order keys;

    • the four commands add, set, remove and style over addresses, under the library’s invariants;

    • a store whose command journal gives undo and redo;

    • the workspace file <name>.tle.json (format version 7), named by default after the workspace.

  • Drawing (layout, writers). Every manifest is drawn as one block opened by its title, a manifest without timelines as that block and title alone:

    • groups as frames, and each timeline as a root in a card; a member of several groups gets a card in each of their frames;

    • a member that is a child timeline drawn with the lines of its ancestors beside it, each on the side opposite to that ancestor’s children band (below the member by default), which its timestamps’ lines cross, and its root drawn whole as an ancestor card behind the group’s frame, unless a style rule hides it;

    • elisions, stretches of a timeline left out of the drawing: every row crossing the stretch stops where it starts and resumes where it ends, at full scale on either side, with a narrow gap between that holds one ellipsis (three dots) centred in it and, below it, the elision’s name (its timeline’s name where it has none; where the names of neighbouring gaps would run into each other, one moves a line down, never widening its gap); its ID, its elided coordinates and grey continuations of the rows across the gap are shown on request. An elision on a timeline in no group elides the cards that draw its root whole: an ungrouped root’s card and its ancestor cards. An elision on a timeline that lies in a group elides that group’s frame at one place in every member card, and the ancestor cards behind the frame carry its gap. A style rule on a root’s cards chooses what they draw: Full (no elision), Custom (the stored elisions) or, on an ancestor card, Proportional, where the card elides by itself what lies outside its member, one gap for each stretch that the member’s ancestors and their other children cover there, on the rows chosen, each such timeline keeping its start and end at full scale, at a proportion that by default fits the card into the view; a root’s cards draw their stored elisions where it has any and Proportional otherwise;

    • arrangements, a block’s groups and ungrouped timelines placed in an order instead of at their own places: Vertical, one under another, or Horizontal, side by side in one row, where every root that a group hangs on (one of its members lying inside that root) is drawn once behind the row, the roots one under another, and each group stands where its first member inside the root lies on it. Along every root the groups follow the row from left to right without overlapping (touching is allowed), and in every group those members lie in the order of their roots; where no row satisfies both, Horizontal is refused with the reason ("Theme A" and "Theme B" overlap on "Score" (8–16 ♩)) and the groups are drawn one under another. The root drawn once keeps, over each group, the scale of that group’s frame, and changes it only between two groups: in a gap that leaves out what the room between their frames cannot show, or, where the two members touch or lie too close for a whole unit, at a seam, which leaves out nothing and across which the root’s line runs on. An arrangement is placement, stored with the block, never in the manifest;

    • a timeline of unknown length scaled to its content and ending in three chevrons;

    • flow control drawn once per root, in the root’s flow control band, for its whole tree: each repeat, segno, coda, dal segno, da capo and double or final barline as its music symbol, each jump’s volta endings as a fork of arrows, one per ending with its passes, breaks, section breaks and barlines as lines (only a break red; a section break dark blue-grey and dashed, with its final barline symbol, a barline dark grey), each element’s name and label by default, its ID too where a style rule asks; the arcs of the jumps hidden unless a style rule shows them; a member that is a child timeline showing its root’s flow control on its own stretch, and hiding a root’s flow control band hiding that of its whole tree;

    • regions in rows of their own, a child’s included, atomic sections hidden unless a style rule shows them, and a label that does not fit beside its neighbour moved to a further tier, joined to its region by a thin leader line;

    • children whose band orders agree drawn in rows that lay out their bands together, each child keeping its row whatever the width of its labels, which the row’s label tiers keep apart, with leader lines where they move;

    • named timestamps, each wedge turned about its tip by its rotation, and groupstamps, whose dashed line runs across every member card of their group’s frame;

    • named MatchStamps, each alignment anchor a line between its two match timestamps, the MatchStamp’s name at the middle one;

    • element descriptors, SVG and TikZ as the TimeToShare drawing specification defines them.

  • The canvas (arranger), built on Svelte Flow. Each completed gesture is one undoable command.

    • Blocks are dragged with snapping, reordered, selected and deleted, and so are timelines, groups and the other elements of a manifest, except segments, whose deletion is not supported yet.

    • A press on a box selects that box, a timeline’s cards, a group’s frame or the block; the card or frame under the pointer is highlighted.

    • Every block, frame and card is resized in the same three modes, Scale, Box and Stretch. A member’s card is resized in the frame it is worked in, its size stated through that group.

    • A press on a gap, its ellipsis or its labels selects its elision. A selected stored elision shows a handle on each edge of its gap and, above it, a menu of two toggles in the resize modes’ look, Coordinates (1) and Width (2), one or both pressed: dragging an edge with Coordinates moves the elided coordinate at that edge, snapping to the ends of the timeline and of its children, with Width it widens or narrows the gap, with both the gap swallows the line and what lies beyond the edge stays put. [ and ] choose the edge the arrow keys move by one grid step, and Delete removes the elision. An elision a card derives by itself is selected but not edited: choosing Custom stores it first. With Show coordinates on, a gap says what it leaves out. When elisions change, the card’s elements slide sideways to their new places.

  • Editors on the canvas. A double-click opens a block, a group or a timeline in its bundle, group or timeline editor.

    • Done, or a double-click outside the edited element, keeps the changes as one journal entry; Cancel discards them.

    • Undo takes back a closed editor’s changes by runs: the consecutive changes made in that editor and not in one nested in it. In the open editor its own changes are undone one at a time. Redo re-applies what undo took back, step for step.

    • In a timeline editor, the edited timeline’s bands (markers, conversion maps, children, regions and flow control, stacked above and below its line) are selected and moved by drag, or by Ctrl or Cmd and an up or down arrow. Each move is one command that sets the timeline’s band order in its manifest.

    • In the timeline editor of a child, a read-only band below the child shows the flow control of its root’s tree that lies on the child’s stretch, as the root’s band draws it, labelled “Flow control (from )”. It is a view only: nothing in it is selected or moved, and it is no part of the drawing, its exports or the manifest.

    • In the bundle editor, groups’ frames and ungrouped timelines’ cards are dragged freely while the block is not arranged. Dragging one that is in the selection moves everything selected by the same travel and keeps the selection.

    • Arranging. The Arrange button of the canvas toolbar opens a menu in the resize modes’ look: on the arranger it arranges the blocks, Free (each at its own place), Vertical, Horizontal or Matrix, with its number of columns (− and +; at first the smallest number whose square holds the blocks), packed 32 units apart in the blocks’ order from the top-left corner of all the blocks’ own places, which reordering does not move; in a bundle editor it arranges the edited block’s groups and ungrouped timelines, Free, Vertical or Horizontal, Horizontal disabled with its reason where they cannot stand side by side. While a level is arranged, nothing lies at a free place: dragging a block or an item shows the others at the places its drop would give them and the release stores the new order, and the arrow keys move the one selected block or item one place along the arrangement (in a Matrix, Up and Down one row). Side by side, a drop or a step that would put a group on the wrong side of another along a root is refused with the reason ("Recapitulation" stays right of "Exposition", "Development" on "Score"), and in a group’s editor the cards anchoring the group on its roots cannot be dragged, and a drop that would change which member anchors it is refused (would anchor "coda" on "Score" instead of "Recapitulation"). Every choice, drop and step is one undoable command; Free puts everything back where its places state, which an arrangement keeps.

  • The editor (editor). One component that the page served by tilie uses, and that any other page can mount with pnpm build:embed’s tilie.js (embedding). Among its options, storage.userKey and storage.profilesKey name the localStorage keys of the user and of the type profiles (the page served by tilie uses tilie.user and tilie.profiles; without a key nothing is stored), and lookup: false turns every lookup request off.

    • A header with a File menu (New workspace, Open…, Save, Save as…, Import manifest…, Export manifest…, Your name…, Type profiles…), an Examples menu that adds one of four example manifests from TimeToShare as a new block or opens the example workspace “Timestamps” in place of the open one (asking first to save or discard unsaved changes), the workspace’s name, renamed in place by a click on it, and an About button, the canvas, and an inspector drawer opened by a tab at the right edge.

    • Manifests are imported from TimeToShare manifest files in YAML or JSON, each as a new block at the centre of the view, moved right past the blocks it would overlap (an open editor is closed first, as Done closes it). Export writes each bundle back as its file came: in the minimal or the complete form, with or without its styling, and in canonical YAML, pretty JSON or RFC 8785 JSON, the file named after the manifest’s id, else its name, else bundle. A new bundle is written minimal, with its styling, in YAML; the Manifest and Bundle tabs set Minimal and Include styling for each bundle, and the workspace keeps these settings. Open… takes manifest files too: into an empty workspace they are imported at once, otherwise it asks whether to add them or to open them in a new, empty workspace, saving unsaved work first. Save (Ctrl+S) writes the workspace file back into the file it was opened from or last saved to, a restored workspace’s included, and otherwise asks for a file; after a rename it asks again, offering the new name. With tilie started on your own computer, Open…, Import manifest… and Save as… use the editor’s own file dialog over your workspace, manifest and table files below the server’s root folder (none in a hidden folder), in every browser, and the workspace remembers where each manifest’s file lies, relative to the workspace file. Without a server, and with a server that offers no files (a public instance), they use the browser’s pickers where it has them, else a file input and a download.

    • The inspector’s tabs wrap into rows where the drawer is too narrow for one. Its first tab, named by the level in view (Arranger, Bundle, Group or Timeline), names the workspace or the edited element; the Arranger tab also arranges the blocks and the Bundle tab the edited block’s groups and ungrouped timelines, with the Arrange menu’s own buttons, disabled with it while the canvas is locked, and the Bundle tab also holds the bundle’s Minimal and Include styling, as the Manifest tab does. Its Properties tab renames the workspace or the inspected element, shows a selected region’s start, end and length and a selected jump’s destinations (each naming where it leads; choosing one selects the jump with its target), toggles how flow control is drawn (arcs, symbols, forks and the name, ID and label of a band’s elements or of one element) and whether atomic sections are shown, each toggle one style rule in the manifest, edits the geometry of the selected block, frame or card, puts the selected timelines into groups or takes them out (a timeline may be in several groups), lists a selected group’s members to change them, and creates a new group of the selected timelines. Its Metadata tab shows and edits statements (below). Its Manifest tab shows the selected block’s manifest as Export writes it, as JSON, YAML or TOML, edits it, and lists unknown keys and the manifest’s own warnings. Its Journal tab lists the journal, newest first. Its last tab, Elisions, sets the elisions of what is selected (below).

    • Elisions. Selecting one elision on the canvas, stored or one a card derives, shows the Elisions tab, as choosing it would: an open drawer switches to it, a closed one shows it when opened, and the tab stays once the selection leaves the elision. The tab shows up to three blocks, each collapsed to one line that names its kind (Timeline, Group or Elision), its title and its mode (with the number of elisions where it lists them), or an elision’s stretch, and opens with a click; the block holding the selected elision and that elision’s own are open from the start, a block the user has acted in (a mode, option or toggle chosen, a button pressed, a listed elision clicked) stays open once the selection leaves it, one closed while it held the selected elision stays closed, and a block stays open or closed while another tab is shown. The timeline block shows the elisions of the root the selection lies under, wherever that root is drawn whole: “Parent timeline” for a root drawn as an ancestor card behind its grouped children’s frames, with the modes Hidden (no ancestor card), Full, Proportional and Custom, and “Elisions of” for an ungrouped root, with Full and Custom. Proportional sets the proportion (Automatic, or a number), the rows that are elided (Automatic, or the rows chosen) and what every gap shows (Ellipsis, Name, Coordinate, Lines). Custom lists the stored elisions the card draws, a click on one selecting it and × deleting it, with Add elision, which elides the middle third of the selected timeline (on an ancestor card, of its longest stretch outside the member’s span), and Remove all; switching from Proportional to Custom stores the gaps the card derived exactly as they were drawn, and the stored elisions are kept while another mode is chosen. Custom is unavailable, with the reason, where the root is a member of a group, whose elisions are then that group’s. A root drawn once behind a row of groups side by side shows the elisions of that one card, wherever the selection lies under it, with its proportion the least of those its groups would give it; “Side by side” lists, read-only, the gaps the row cuts in it between two groups, and Custom lists the stored elisions lying between its first group and its last as not drawn while arranged side by side. Wherever the selection lies in a group’s frame, or in its group editor, the group block, “Elisions in group”, offers Full and Custom, lists the group’s elisions, and adds and removes them in the same way. A selected elision is renamed in the Properties tab’s Name field, and its own block is its form: From and To in its timeline’s unit, typed exactly, its gap’s width (Standard, 32 units; Proportional, of its natural width; As wide as, a stretch of its timeline; Fixed, in units of the canvas), changing from one form to another without moving the gap, what it shows (Ellipsis, Name, ID, Coordinate, Lines), for a group elision the stretches it also elides on the other timelines of the frame, and Delete elision; an elision a card derives is shown read-only (“Choose Custom to edit”). Each change is one undoable command, and every mode is a style rule stored in the manifest, so an export draws what the canvas shows.

    • Statements. The Metadata tab shows what the selected bundle, timeline or region stands for (with nothing selected, the edited element in an editor, else the bundle when the workspace holds one block), as property–value pairs that TimeToShare’s description specification defines, each with its provenance: how it was made (who stated it, when and how) and who believes it (true, unlikely or false). One tile holds one verb about one thing (two values carrying the same label count as one thing), collapsed to its sentence, with the image of the first of its things that has one; the first one says what the element is (“Clair de lune, mm. 1–6 (MEI) is a printed or scanned edition.”). One click on a tile’s expand button shows its pairs, one row per vocabulary that states it (rel:prf, schema:byArtist, wdt:P175, …), each with a Provenance button, and “＋ Add vocabulary”; an IRI is shown as a slug, prefix:local (mbid: for MusicBrainz), the full IRI on hover. Provenance opens the pair’s paradata and beliefs and holds the actions: your own belief, True, Unlikely or False, and Remove; believing a pair false records your belief and leaves the pair stated. Below the tiles, the candidates (pairs held only in provenance, such as matches proposed for review) are listed with the same Provenance button, believing one true states it, and those you believe false are set apart. “＋ Add statement” opens the composer, three fields each narrowing the next: the verb, the vocabulary, and the value, searched in Wikidata, the GND, YouTube or MusicBrainz, entered as an identifier, or a timeline or region of the manifest chosen from a list or picked on the canvas; a URL pasted into any field fills vocabulary and value, and “Other property…” states a property no vocabulary of the catalogue offers. “＋ Add vocabulary” offers what other systems say the thing is the same as. “Propose matches for unreconciled names” looks up every name stated without an identifier and writes the best match as a candidate. Every action is one undoable command. What you add is stated by you and believed true by you: your name, “Gerhardt” until you give one under File, Your name…, is also the journal’s author, and your ORCID iD, where you give one, names you in the provenance (else a tag: IRI made from your name); the browser keeps both. Type profiles (File, Type profiles…) are your own types of thing, with the verbs usually stated of each and the systems to look its values up in, any Reconciliation Service API endpoint among them; they are settings of the browser, exchanged as YAML files, never part of a workspace or a manifest.

    • Lookup and privacy. Text typed into a value field goes to the chosen system’s service: Wikidata, the GND (through lobid) and YouTube’s oEmbed are asked from the browser, MusicBrainz only through tilie-server (one request a second, a User-Agent naming the server and no person, answers cached for the run). Viewing the tab also resolves the IRIs of the things its tiles name, for their thumbnails, and “＋ Add vocabulary” resolves a tile’s thing for its cross-references, so the manifest’s thing IRIs reach Wikidata, the GND, YouTube or the server. An editor mounted with lookup: false sends none of these requests.

    • Timestamps. A timestamp is a timeline’s cross-section at a position: the timeline’s coordinate, that of every segment and displayed descendant its cross-section line crosses, and the values of their conversion maps. With Show coordinates on (the canvas toolbar, or C), hovering a timeline or one of its maps shows that timestamp in a flag, the position picked on the hovered row (an ancestor line is read as its ancestor’s line, and the lines of an ancestor card where the card is seen beside the frames and cards in front of it, everywhere while it is raised), and a click pins it in the Timestamp tab: there its exact values are copied bare, with their unit written out (219/16 quarters) or pretty (13 11/16 ♩, 1′15.5″), shown as JSON, YAML or TOML, and edited, every coordinate and every map value that can be solved for a position. The flag and the tab also show the coordinates of the timeline’s ancestors, every coordinate and map value listed top to bottom as it is drawn on the canvas (a map drawn above its timeline’s line before that timeline’s coordinate); while Show coordinates is on, named timestamps and MatchStamps let the pointer through to the lines beneath; a segment’s boundary, selected alone, shows the segment’s start in the tab; and on a timeline of an integer unit (samples, ticks, pixels) the pointer steps by 1. Giving a pinned timestamp a name stores it in the manifest as a named timestamp, whose Display toggles choose what every export draws of it: its wedge, its name, ID and coordinate as stacked labels, and its dashed cross-section line (Line). The Wedge slider turns the wedge about its tip from −180° to 180°, mirrored when its band lies above the line, with stops at −180, −135, −45, 0, 45, 135 and 180 (PageUp and PageDown move between them); Default removes the stated rotation. On a member of a group a named timestamp may be a GroupStamp (the GroupStamp toggle; on by default when it is named on the arranger or in a bundle or group editor, off when named in a timeline editor): its line runs across every member card of the group’s frame, the other members’ coordinates follow from the group and are never stored, and its coordinates on the other members are secondary coordinates, hidden unless a rule shows them. With Show coordinates off, a click on any of its lines shows the whole GroupStamp in the Timestamp tab; with it on, the flag reads a hovered member’s line the same way above a timeline editor, listing every member of its group with its ancestors and the descendants its line crosses. Every new root timeline, and every root of an imported manifest without a graphical object, is given the named timestamps origin and length (when its length is known), each drawing its wedge and coordinate; a timestamp at a timeline’s end follows the end when the length changes. With Show coordinates off, a click on a named timestamp shows it in the tab, where it is renamed, moved by editing its values, or deleted. Two settings at the bottom of the tab cap how finely a position is picked: Denominator (2520 by default) for fraction axes and Decimals (3) for float axes, which also sets how values are rounded in the flag; the pointer takes the simplest value inside its pixel on the hovered row’s axis, and zooming in reaches finer ones. The message bar over the canvas lists every message as a card that names its level: information, such as “Copied” or the reason a gesture, a key or a choice was refused, vanishes after three seconds, a longer text after 300 ms a word; warnings (something asked for and left undone) and errors (an operation on a file or a server that failed) stay until dismissed.

    • MatchClaims and MatchStamps. A package’s MatchClaims lie in its MatchClaim table, a Parquet file beside the manifest, which the manifest names in its resources; the editor reads one table per block through tilie-server, so matches need a running server: until one has answered its health check, nothing is asked: turning Show matches on while a table is missing says in the message bar, for as long as it takes to read, that matches need a running tilie-server and how to start it, and the disabled Load MatchClaims… and belief buttons and an expanded MatchClaim say the same; while the check has not answered yet, the message bar says nothing: once it answers, the tables Show matches asks for load, and if it fails, the message bar says once how to start a server. Turning Show matches on (the canvas toolbar, or M; it and Show coordinates take turns) loads the table each block’s manifest names, without a question: from its URL where the manifest names it by an http or https URL, else from beside the manifest’s file where the workspace knows where that file lies; only where the file cannot be found does one small dialog per block ask, to locate the manifest or the table in the file dialog, to enter a URL, or to cancel, and a located manifest is remembered with the workspace; where no block holds a table afterwards, the message bar says “No MatchClaim table loaded.”. A table can also be picked beside its manifest in Import manifest… or beside its workspace in Open… in the browser, and is read through the server too, or chosen with Load MatchClaims… in the Matchstamp tab, which opens the same dialog. A server that offers no files (its health answer says "files": false, as a public instance’s does) still reads the tables, so Load MatchClaims…, Show matches, beliefs, provenance and events all work with it: a table the manifest names by an http or https URL is loaded from there, an example’s from where the example is served, and otherwise the dialog asks for the table itself, whose Locate… opens the browser’s file picker for one .parquet file, or for its URL; where a picked file lies is not remembered, so it is picked again after the workspace is reopened. Tables are held while the workspace is open and never written into it.

    • The table’s potential MatchStamps, the connected sets of alignment anchors its MatchClaims state, are drawn over the block as dashed grey lines, wherever a line of their timelines is seen; hovering one shows its coordinates in a flag, and a click pins it in the Matchstamp tab, the hovered and the pinned one drawn as naming would draw them, a GroupStamp’s line across its group’s frame. What naming stores is the same whichever editor is open. Giving it a name stores it in the manifest as a named MatchStamp, whole, as the table states it, even where the MatchClaim filter hides some of its timelines. The anchor lines of the pinned MatchStamp and of the named ones take your belief in the MatchClaims stating them: undecided blue, true green, unlikely dark orange, false red, the most critical belief where several MatchClaims state one anchor. A named MatchStamp that the table no longer matches is drawn entirely red, with an exclamation mark before its name; the Matchstamp tab lists what differs, and Update rewrites it from the table. With Show matches and Show coordinates off, a click on a MatchStamp’s connector, or on one of its match timestamps’ lines, selects it for renaming, Update and Remove.

    • The Matchstamp tab shows the MatchStamp’s coordinates as the Timestamp tab shows a timestamp’s, disabled, with the same Copy buttons, the coordinates its MatchClaims state set apart from those reached through groups, ancestors and crossed lines, or as JSON, YAML or TOML; its Lines, every dashed line it draws in screen order, each timestamp line with the Timestamp tab’s display toggles and, on a timeline in a group, a GroupStamp toggle (a named MatchStamp’s match timestamps on grouped timelines are GroupStamps by default), and each anchor line with Line and Name, which choose what every export draws; and its MatchClaims, each collapsed to its ID. Expanded, a MatchClaim shows the events on both sides, its certainty and every actor’s belief; True, Unlikely and False record your own belief, which the server writes into a new table, kept only once Save MatchClaims… saves it (New workspace and Open… ask before they drop a changed table); Provenance opens how it was made. The MatchClaim filter at the bottom of the tab chooses the timelines whose MatchClaims are shown and, with four toggles, the beliefs that count: true, undecided, unlikely and false, all but false by default; the workspace keeps it for each block.

    • Unsaved changes are marked with • before the workspace’s name in the header. A workspace’s text is autosaved in the browser’s IndexedDB and offered for restoring when the editor opens again.

Not available yet: editing flow control in the editor beyond an element’s name, its label, the user’s belief in it and how it is drawn, and showing a timeline’s computed flows; loading sources through timetoalign on the server, which so far exposes /api/health, whose member files says whether the server offers the file routes, /api/measure-maps, the expansion of a manifest’s measure maps, /api/match-claims, a package’s MatchClaim table checked against its manifest and answered as columns, /api/match-claims/provenance and /api/match-claims/belief, a MatchClaim’s provenance read on demand and a belief recorded in a new table, /api/match-claims/events, the events on both sides of given MatchClaims, /api/flows, a timeline’s flow control played by timetoalign, /api/flows/flow-maps, the manifest with a timeline’s flows written as regions and FlowMaps, /api/reconcile/musicbrainz, MusicBrainz as a Reconciliation Service API 0.2 endpoint, and, except on a public instance, /api/folders and /api/files, the workspace, manifest and table files below its root folder listed and read and workspace files written, nothing in a hidden folder.

Install and start#

The tilie-server release on PyPI predates the editor described above. Until a release carries it, build the editor and start the server from the source tree, with TimeToShare and timetoalign cloned beside this repository as Development describes:

cd TimeLineEditor/app
pnpm install
pnpm build
cd ../server
uv sync
uv run tilie --static-dir ../app/packages/editor/dist

With a release that carries it, pip install tilie-server and then tilie do the same.

tilie starts the local server on 127.0.0.1, port 8000, and opens the browser (the release on PyPI, which predates this, chooses a free port each time). The browser keeps what the editor remembers, such as your name and your type profiles, for each port apart, so the port stays the same from run to run; while port 8000 is taken, tilie uses a free port and prints a notice saying so. Use tilie --check to verify an installed distribution. tilie --port 43129 selects a port, tilie --no-browser starts without opening a browser, and tilie --root <folder> narrows the files the editor may open and save to that folder (by default your home folder).

Open, save and reopen a workspace#

With the server running, the editor reaches your files below the server’s root folder through its own file dialog, so it works the same in every browser:

  1. File, Import manifest… adds a TimeToShare manifest file (YAML or JSON) as a block. The workspace remembers where the manifest’s file lies.

  2. File, Save (Ctrl+S) asks once where to save the workspace and offers <name>.tle.json after the workspace’s name; later saves write it back in place. Save writes the workspace file alone, which holds its own copy of every manifest: the manifest files and their tables stay as they are, and Export manifest… writes a manifest out. The workspace keeps each manifest’s place relative to its own file, so a folder holding both can be moved as a whole.

  3. A click on the workspace’s name in the header renames it; the next Save then asks again, as Save as… does.

  4. File, Open… opens the workspace file again later, in this or any other browser.

  5. Show matches (M) loads each manifest’s MatchClaim table from beside the manifest’s file, or from its URL where the manifest names the table by an http or https URL, without asking. Only when a file cannot be found does a small dialog ask you to locate the manifest or the table, to enter a URL, or to cancel; a manifest you locate is remembered with the workspace.

The file dialog shows only workspaces (.tle.json), manifests (.yaml, .yml, .json) and MatchClaim tables (.parquet), and nothing in a hidden folder or with a hidden name (one starting with .): a workspace or manifest kept in a hidden folder cannot be opened, imported or saved through the server, so keep your files in folders that are not hidden. The server writes only workspace files: File, Export manifest… and the Matchstamp tab’s Save MatchClaims… are saved by the browser, as a download or in the browser’s own save dialog, never through the server.

Without a server, or once the page has been reloaded and lost the run’s token (the header then shows “offline”), the editor opens and saves through the browser’s own pickers and downloads, and reads no MatchClaim table (Status).

A public instance#

tilie --public-host <host> serves the editor to anyone who reaches <host>, so that TiLiE can be tried without installing anything. The option names the host exactly as browsers send it in the Host header (tilie.example.org, or localhost:8000 for a trial on your own computer) and may be repeated for a server reached under several names. A public instance:

  • binds every interface, on port 8000 unless --port names another, opens no browser and prints tilie: public mode on port <port>, answering as <hosts>; no token, no file access;

  • answers only requests addressed to the named hosts, from no page but theirs (403 otherwise), and needs no token;

  • serves none of your files: Open…, Import manifest… and Save use the browser’s pickers and downloads, while measure maps, Show matches and the MusicBrainz lookup work as on your own computer;

  • refuses with 413 a posted body over 16 MiB and a MatchClaim table of more than 1,000,000 rows or over 128 MiB uncompressed, runs at most two computations at once (further ones wait) and holds at most 32 connections.

--check, --root and --no-browser cannot be combined with --public-host. A public instance has no rate limit, one MusicBrainz queue shared by all its visitors (one request a second for all of them), and no accounts, and it stores nothing: a visitor’s work lives in their browser and in their downloads. decisions/0038 records why it is built so.

To try it from the source tree, build the editor as above and start, from server/, uv run tilie --public-host localhost:8000 --static-dir ../app/packages/editor/dist; then open http://localhost:8000/ (127.0.0.1:8000 is a host it was not given).

The container image. The Dockerfile at the repository root builds the editor and the server into one image that starts a public instance. The build fetches timetoalign and TimeToShare from GitHub at the commits named by the build arguments TIMETOALIGN_REF and TIMETOSHARE_REF, by default fixed ones (timetoalign’s the commit server/uv.lock was locked against). From the repository root:

podman build -t tilie .        # or: docker build -t tilie .
podman run --rm -e TILIE_PUBLIC_HOST=localhost:8000 -p 127.0.0.1:8000:8000 tilie

The image runs as an unprivileged user and reads TILIE_PUBLIC_HOST, the host it answers as (else RENDER_EXTERNAL_HOSTNAME; with neither it refuses to start), and PORT, the port it listens on (8000 by default). It speaks plain HTTP and expects TLS to be terminated in front of it, as a hosting platform does. To host it on a platform:

  1. Let the platform build the Dockerfile from this repository.

  2. Leave PORT to the platform, which sets it.

  3. Set TILIE_PUBLIC_HOST to the public host name of the service. Render sets RENDER_EXTERNAL_HOSTNAME, which the image reads by itself.

  4. Address a health probe to that host name: a probe sent to the container’s internal address is refused with 403. Use /api/health only where the platform sends the public Host with its probe, else a TCP check.

The image was designed for Render’s free web service and for Google Cloud Run. A free Render instance has 512 MB of memory, sleeps after 15 minutes without traffic, takes about a minute to wake and keeps nothing on disk; Cloud Run scales to zero when unused, lets you choose the memory and needs a billing account. These terms change: see Render’s free instances and Cloud Run pricing.

Status#

Started as tilie, the server binds only to 127.0.0.1, creates a random bearer token for each run, rejects foreign Host and Origin headers, serves the bundled application, protects every /api/ route, and sends Referrer-Policy: no-referrer with every response. tilie prints and opens http://127.0.0.1:<port>/#token=<token>: the token travels in the URL fragment, which the browser never sends to the server. The editor reads it, removes it from the address bar, and sends it with its health request. The token is held in memory only, so reloading the page loses it and the header then shows the “offline” mark; restart tilie for a fresh URL. Started with --public-host, it keeps the Host and Origin checks for the named hosts and the referrer policy, and gives up the token and the file routes (A public instance).

Of the six application packages, core implements the workspace, block, and manifest model described in the architecture guide. It reads and writes manifests of schema 0.2.0 only, the one version TimeToShare supports, and migrates nothing. layout exports draw(manifest, placement, layers, metrics), which returns one derived drawing. writers exports toDescriptors(drawing), writeSvg(placed), and writeTikz(placed, options); a placed drawing has drawing, x, y, and scale, and a page may contain more than one. arranger exports the canvas and the functions that turn its gestures into commands (the canvas); editor is the application around it (the editor); client connects to the server, lists and reads the workspace, manifest and table files below its root folder and writes workspace files there, and asks its health, the expanded rows of a manifest’s measure maps, the columns of a package’s MatchClaim table, the provenance of some of its MatchClaims, the events on both sides of some of them and the new table holding a belief. There is no generated API client, server-side loading or export endpoint yet.

Architecture#

TiLiE keeps a small browser editing core and treats the local Python server as an equal peer for loading, computation, and exports. TimeToShare manifests remain exact and schema-validated, while the screen drawing is derived from them. The package structure prevents UI dependencies from leaking into the core. Read the architecture guide for the complete design and the distinction between current behavior and intended behavior.

Development#

Every application package that uses the TimeToShare schema package, @timetoalign/timetoshare, takes it through a link: to the js/ directory of a checkout beside this repository until schema 0.2.0 is published on npm, and ^0.2.0 from npm once it is. Clone TimeToShare there and build its js/ package first (see CONTRIBUTING.md), then install and validate the application workspace:

git clone https://github.com/TimeToAlign/TimeLineEditor.git
cd TimeLineEditor/app
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build

To render the writer review sheet, install rsvg-convert and run this from the repository root:

pnpm -C app/packages/writers review

The command writes SVG and PNG renders plus index.html under app/packages/writers/review/. It confines fontconfig to the DejaVu Sans and Noto Music files bundled by TimeToShare and refuses to render when another font is visible.

To draw any manifest file as the drawing fixtures are drawn, into an SVG file and a standalone TikZ document:

pnpm -C app/packages/writers draw path/to/manifest.yaml --out path/to/folder

Relative paths are read from app/packages/writers; --name, --length and --scale are described in AGENTS.md.

Set up, test, and build the server separately. Until a timetoalign release carries the measure-map expansion, the server installs timetoalign from a checkout beside this repository, so clone timetoalign there first; until a TimeToShare release carries schema 0.2.0, the timetoshare package that timetoalign checks statements with comes from the TimeToShare checkout cloned above (see CONTRIBUTING.md):

cd ../server
uv sync
uv run pytest
uv build

The writer compile test needs lualatex with TikZ, standalone, and fontspec; it uses the DejaVu Sans and Noto Music files bundled by TimeToShare. Without lualatex the TikZ compilation is skipped, and with TILIE_REQUIRE_LUALATEX=1 set its absence is a failure, as in CI. The same test parses every review SVG as XML.

The server wheel bundles the built app. From server/, uv run tilie --check --static-dir ../app/packages/editor/dist checks a development build. From the repository root, python3 scripts/check_versions.py --tag vX.Y.Z checks that a release tag matches both declared versions.
