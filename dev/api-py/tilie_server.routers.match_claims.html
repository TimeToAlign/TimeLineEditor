tilie_server.routers.match_claims#

The MatchClaims route: a package’s MatchClaim table as the editor’s columns.

The editor has no Parquet reader. It posts the manifest file’s text together with the picked match_claims.parquet; the route reads the table with timetoalign, checks it against the manifest with TimeToShare’s table checks and answers with the columns the editor’s anchor index takes, as raw little-endian arrays behind a small header, which the browser views where they lie. The repository’s decisions/0029-match-claim-columns.md fixes the arrays and their encoding, decisions/0030-match-claims-answer.md the bytes of the request and of the answer.

Besides the columns the answer holds every row’s beliefs, from which the editor computes the belief filter’s row mask; the route filters nothing.

A server may bound the tables it reads (TableBounds): a public server does, since a small Parquet file can decode to a table many times its size. Every route that reads a posted table reads it through the reader table_reader() returns, which keeps to the server’s bounds.

pyarrow, TimeToShare’s table checks and timetoalign’s MatchClaim table are imported when a request needs them, so a server whose installed timetoalign or timetoshare lacks them still starts and answers every other route; this route then answers 501.

tilie_server.routers.match_claims.bounded_table(parquet, pyarrow, data, bounds)[source]#

Read Parquet bytes into an Arrow table, within bounds.

Without bounds the file is read whole. With them, the footer is checked first, before any row is decoded: its rows (the file’s count, or the sum of its row groups’ where that is larger, since the reader follows the row groups) and its row groups’ summed total_byte_size. The footer is the sender’s statement and measures encoded pages, so the table is then decoded BATCH_ROWS rows at a time and the bytes of the decoded batches are summed; the read stops at the batch that passes the size bound. One batch is thus decoded before it is counted.

Raises:

Refusal – 413 as TableBounds.check_rows() and TableBounds.check_size().

The table as timetoalign reads it, once TimeToShare’s checks accept it.

tilie_server.routers.match_claims.answer_bytes(header, arrays)[source]#

Write the answer: the header’s length, the header, then the arrays.

tilie_server.routers.match_claims.match_claims(body, bounds)[source]#

Answer the columns of the posted MatchClaim table, checked against the posted manifest.

The body is the manifest file’s length in bytes (a little-endian 32-bit integer), the manifest file’s text in any serialization, then the Parquet file. A body that cannot be split or read, or a table the checks refuse, is answered 422 with {"detail": {"path", "message"}}, a refused table with problems besides (each {code, row, column, message}, the checks’ own); a table beyond the server’s bounds 413 in the same form; a server that cannot read or check MatchClaim tables, or read manifest files, 501.
