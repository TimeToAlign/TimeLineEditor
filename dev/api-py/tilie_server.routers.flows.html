tilie_server.routers.flows#

The flow routes: a timeline’s flow control played, and its flows written.

A manifest states where the flow of a timeline jumps and breaks (its flow control); in which order its stretches are then played is computed, and the computation is timetoalign’s alone. The editor asks for the flows of one timeline (POST /api/flows): its atomic sections, and for each convention the runs played, the sections they cover and what playing found, each finding with its cause where timetoalign names one. When its user wants those flows in the manifest, it asks for the manifest with them written (POST /api/flows/flow-maps): the atomic sections as Regions of the timeline and the computed FlowMaps. A manifest that holds flows written before is written again: a Region whose stretch is an atomic section no longer stays and is rejected as one, which needs the actor who asks. The server stores nothing; what is done with either answer is the editor’s.

Both requests are a JSON object of parameters behind its length, as the MatchClaim provenance routes take them, followed by the manifest file’s text, in any serialization timetoshare reads, to the end of the body. The manifest is read whole by timetoalign, which checks it as a manifest reader does, before the timeline is looked for.

timetoalign’s engine and what reads a posted manifest for it are imported when a request needs them, so a server whose installed timetoalign cannot play flow control still starts and answers every other route; these routes then answer 501.

tilie_server.routers.flows.asked_reading(parameters)[source]#

Whose beliefs decide which elements are read, where a request says so.

believer is an actor, compared as timetoalign’s engine compares it with the actors of the elements’ beliefs as the manifest writes them; beliefs the belief states read for it (true, undecided, unlikely, false), every state but false without it. An element is read when the believer’s state in it, undecided where they hold no belief, is one of them; without a believer, when no actor rejects it.

Returns:

The keyword arguments of timetoalign’s play, atomic_sections and create_flow_maps_from_flow_control that say so: none without a believer.

Raises:

Refusal – 422 at ["believer"] if the believer is no string; at ["beliefs"] if the states are no list of belief states, or are given without a believer.

Parameters:

parameters (Mapping[str, Any])

Return type:

dict[str, Any]

tilie_server.routers.flows.flows_answer(body)[source]#

The flows of the timeline a request names.

Returns:

{"timeline", "number_type", "atomic_sections", "conventions"}, the timeline’s bare ID and number type; its atomic sections in the order of the axis, each {"name", "start", "end"}; and under each convention answered {"runs", "sections"}, the runs played as [start, end] pairs (stretches played one after the other without a jump between them are one run) and the names of the atomic sections they cover, in the order played, and findings, what playing found, each {"kind", "coordinate", "message"} with the end of a stretch never played and, where timetoalign names one, the cause (single_playback: a stretch the single flow leaves out that the default flow plays); printed finds nothing. Every value on the axis is written as a manifest writes a value on the timeline’s own axis: an integer, a number or a [numerator, denominator] pair, as the number type says. A timeline without flow control answers one section and one run over its whole length.

Raises:

Refusal – 501 as flow_engine(); 422 as read_request(), asked_conventions(), asked_reading() and asked_timeline(); 422 at ["timeline"] with timetoalign’s message if the timeline’s length is unknown or its flow control cannot be played.

Parameters:

body (bytes)

Return type:

dict[str, Any]

tilie_server.routers.flows.written_manifest(body)[source]#

The manifest of a request with the flows of the timeline it names written.

Returns:

A manifest file’s text in timetoshare’s JSON serialization, the manifest as timetoalign writes it, in the minimal form, after writing the timeline’s atomic sections as Regions and its computed FlowMaps. A child timeline’s Regions are written on the child and its FlowMaps on the root of its tree, which a FlowMap names. A timeline without flow control has nothing written. Where the manifest holds flows written before, an atomic section whose stretch is still one keeps its Region, a new stretch gets a new Region, and a Region whose stretch is none any more stays, with the belief false of the request’s actor on the request’s date (the server’s day without one) in its type statement; the computed FlowMaps keep their IDs and list the sections standing now.

Raises:

Refusal – 501 as flow_engine(); 422 as read_request(), asked_reading(), asked_rejection() and asked_timeline(); 422 at ["timeline"] with timetoalign’s message if it does not write the flows: the timeline’s length is unknown, its flow control cannot be played, or it holds an atomic section that is none any more and the request names no actor to reject it.

Parameters:

body (bytes)

Return type:

str

tilie_server.routers.flows.flows(body)[source]#

Answer the flows of one timeline of the posted manifest.

The body is the parameters’ length in bytes (a little-endian 32-bit integer), the parameters {"timeline": <bare ID>, "convention"?: "default" | "single" | "printed", "believer"?: <actor>, "beliefs"?: [<belief state>, …]} as JSON, then the manifest file’s text: the elements read are those whose state for believer is one of beliefs (every state but false without it), or, without a believer, those no actor rejects. The answer is JSON (flows_answer()), with all three conventions where none is named. A request that cannot be answered is answered 422 with {"detail": {"path", "message"}}, a parameter’s at its name; a timetoalign that cannot play flow control, 501.

tilie_server.routers.flows.flow_maps(body)[source]#

Answer the posted manifest with the flows of one timeline written.

The body is the parameters’ length in bytes (a little-endian 32-bit integer), the parameters {"timeline": <bare ID>, "believer"?: <actor>, "beliefs"?: [<belief state>, …], "actor"?: <actor>, "date"?: "YYYY-MM-DD"} as JSON, then the manifest file’s text; believer and beliefs read the elements as the computing route does. actor is who asks: the one whose belief rejects an atomic section written before that is none any more, on date.
