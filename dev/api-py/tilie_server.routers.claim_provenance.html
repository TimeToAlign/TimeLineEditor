tilie_server.routers.claim_provenance#

The MatchClaims’ provenance: read for given MatchClaims, and a belief written.

A MatchClaim’s provenance is TimeToShare’s provenance entry: how it was made (paradata) and who believes it. The editor holds a MatchClaim table for its session only and never writes it; it asks the server for the provenance of the MatchClaims it shows (POST /api/match-claims/provenance) and, when its user states a belief in one, for the table that records it (POST /api/match-claims/belief), which the user saves in the place of the old file. The repository’s decisions/0031-match-claim-provenance.md fixes both routes.

Both requests are a JSON object of parameters behind its length, followed by the request of POST /api/match-claims unchanged: the manifest file and the Parquet file the editor holds. The table is checked against the manifest as that route checks it.

tilie_server.routers.claim_provenance.believed_table(table, believed)[source]#

The posted table with the provenance of the table timetoalign wrote.

believed is the posted table’s MatchClaims as timetoalign holds them after recording a belief: the same rows in the same order, the columns the table type declares. Its provenance column replaces the posted one, and the file’s provenance for every row is the one believed states, if any (timetoalign keeps a shared entry only while it is every row’s). Every other column, the columns the table type does not declare included, and the file’s other metadata are kept.

Parameters:

  • table (Any)

  • believed (Any)

Return type:

Any

tilie_server.routers.claim_provenance.belief_answer(body, bounds)[source]#

The Parquet file of the posted table with the posted belief recorded, the table read within bounds.

timetoalign records the belief: the manifest is read as an AlignmentBundle, the table’s MatchClaims are added to it, and its add_match_claim_belief replaces the actor’s earlier belief in the MatchClaim, actors compared as IRIs under every prefix the manifest’s @context declares. The new table is checked against the manifest as a posted one is, and against the posted table by the succession rule, before it is written.

Raises:

Refusal – As read_request(), checked_belief() and tilie_server.claim_columns.manifest_bundle(); 422 with timetoalign’s message if it refuses the MatchClaims or the belief, with the problems if the new table fails its checks or the succession rule.

Parameters:

  • body (bytes)

  • bounds (TableBounds)

Return type:

bytes
