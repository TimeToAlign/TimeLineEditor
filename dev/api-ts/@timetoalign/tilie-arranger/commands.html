deleteQuestion()#

deleteQuestion(view, command): DeleteQuestion | null

Defined in: arranger/src/commands.ts:577

The question command asks before it is stored, where removing its targets also removes virtual timelines it does not name (core’s removedBy: those made from a removed timeline or virtual timeline, or through a removed FlowMap, at any depth); null where it removes none, and for the virtual timelines of a block removed whole. Core refuses to remove a virtual timeline another one left is made from, so “Delete all” names each of them, after the targets, in each block’s order of its virtual timelines. That remove is previewed with core (preview), never checked by a copy of its rules: where core refuses it (a FlowMap left names one of them as a chunk), the question says so in core’s words and offers only hiding instead, where hiding is possible.

removeCommand()#

removeCommand(view, selection, editing): SetCommand | RemoveCommand | { refused: string; }

Defined in: arranger/src/commands.ts:443

What Delete stores for the selected addresses: one remove, an element’s part or card standing for the element whose ID it carries, or one set hiding the selected virtual cards. Every element can be removed, timelines and groups included; a selection holding a manifest’s title, which goes only with its block, is refused whole, with a hint naming the block. A band is never removed: its address is left out, and a selection of bands alone is refused with a hint. Nor is a flow-control element, which is rejected through its provenance and never deleted, nor a chunk of a virtual timeline or of a switched card, which is changed in its FlowMap: their addresses, or those of their parts, are left out, and a selection that names nothing else is refused with a hint. A selected virtual card held by its block is hidden: its place is unstated (core’s set of place with every stated member null) and its virtual timeline kept, which only a remove of the virtual timeline’s own address deletes (the Properties tab’s “Delete virtual timeline”); a virtual card in a frame is left out with a hint, and a selection hiding virtual cards and deleting anything else is refused with a hint. Whether a segment may go is core’s to decide: one that would leave a gap in its segment line is refused there (segment_not_removable), and the canvas shows that refusal as it shows every refusal of the store. Inside an editor the edited element is never removed, a part of it standing for it as well: it is left out of the targets, and a selection that names nothing else is refused with a hint to close the editor first. A remove that also takes along virtual timelines made from what it names is asked about before it is stored (deleteQuestion).

rootDisplayCommand()#

rootDisplayCommand(block, root, hidden): StyleCommand

Defined in: arranger/src/commands.ts:396

The style hiding the root timeline root of the block block (display: none on rootSelector’s addresses), or, with hidden false, removing that rule, so the root is drawn again. Its card keeps its place while hidden (section 8.4); a member of a group lying inside the root is drawn by its frame and stays, without the root’s ancestor line, and the ancestor cards of the root behind frames are not drawn.
