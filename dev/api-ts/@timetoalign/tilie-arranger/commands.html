addCommand()#

addCommand(view, id, manifest, visible, metrics, pane?): AddCommand

Defined in: arranger/src/commands.ts:176

One add of a new block id holding manifest, its top-left at the centre of what visible shows, quantized as a move under the view’s grid is, then moved right past every block it would overlap: while its node rectangle (its drawing at the workspace’s block defaults) meets a root block’s grown by the grid size on every side, its node moves to the right edge of the rightmost such block plus the grid size, its x rounded up to the position step. Its y never changes; its other placement members are the workspace’s block defaults.

moveCommand()#

moveCommand(view, moves, metrics, pane?): SetCommand | null

Defined in: arranger/src/commands.ts:88

One set placing every moved block where its node is dropped, moves holding node positions (the block’s top-left corner, nodePosition): each quantized to GRID_FREE and stored as the position of the block’s place origin, in the order of moves; a block whose stored position does not change is left out, and null is returned when nothing is left. Snapping is snap’s job: the caller passes the dragged node’s snapped position, and the other nodes of the drag moved by the same delta.

removeCommand()#

removeCommand(view, selection, editing): SetCommand | RemoveCommand | { refused: string; }

Defined in: arranger/src/commands.ts:384

What Delete stores for the selected addresses: one remove, an element’s part or card standing for the element whose ID it carries, or one set hiding the selected virtual cards. Every element can be removed, timelines and groups included; a selection holding a manifest’s title, which goes only with its block, is refused whole, with a hint naming the block. A band is never removed: its address is left out, and a selection of bands alone is refused with a hint. Nor is a flow-control element, which is rejected through its provenance and never deleted, nor a chunk of a virtual timeline or of a switched card, which is changed in its FlowMap: their addresses, or those of their parts, are left out, and a selection that names nothing else is refused with a hint. A selected virtual card held by its block is hidden: its place is unstated (core’s set of place with every stated member null) and its virtual timeline kept, which only a remove of the virtual timeline’s own address deletes (the Properties tab’s “Delete virtual timeline”); a virtual card in a frame is left out with a hint, and a selection hiding virtual cards and deleting anything else is refused with a hint. Whether a segment may go is core’s to decide: one that would leave a gap in its segment line is refused there (segment_not_removable), and the canvas shows that refusal as it shows every refusal of the store. Inside an editor the edited element is never removed, a part of it standing for it as well: it is left out of the targets, and a selection that names nothing else is refused with a hint to close the editor first.

zOrderCommand()#

zOrderCommand(view, ids, action): SetCommand | null

Defined in: arranger/src/commands.ts:261

One set of index raising or lowering the blocks ids among their siblings: to the front or back, or one step past their unchosen neighbour. Only the chosen blocks get new fractional indices, each run of them between its unchosen neighbours and below every index a chosen block holds there. null when the order is unchanged.
