# Architecture

## Overview

TimeLineEditor (TiLiE) is a browser editor and visualization tool for musical timelines represented by `timetoalign`. It works with three layers, each named by one word only:

- a **manifest** is one file as the `timeskeleton` schema (version 0.7.0) describes it, of one of three kinds: a **timeline file** `{meta, timeline, graphical?}` holds one timeline with all its descendants; a **group file** `{meta, timelines, group, graphical?}` holds one timeline group and the root timelines that are or contain its members; a **bundle file** `{meta, timelines, bundle, graphical?}` holds one alignment bundle, its groups and every root timeline. A timeline has exact rational coordinates, children at exact offsets, conversion maps, regions, flow control, measure maps and metric hierarchies; `graphical` holds the style rules of the file's own drawing and, in a group or bundle file, the members' display order. Every timeline, conversion map, region, break, jump and marker has an `id` and a `name` where it is displayed. In a timeline file every id is unique within the file; in a group or bundle file the ids of timelines, groups and the bundle are unique across the file, and every other id only within its root's tree. A manifest knows nothing about where, or how often, it is shown;
- a **block** carries one manifest, entirely its own, together with its placement, the other inputs of its drawing: position, scale, graphical length, vertical spacing, requested box size and band order. A block's styling is its manifest's `graphical`; the block has no style layer of its own;
- a **workspace** is the canvas: its blocks, their order, the workspace settings, and the command journal that produced them. Block ids are the workspace's namespace, and an address names anything in it.

TiLiE is local-first from the start: the browser communicates with a local Python server. The server is not an incidental wrapper. It owns loading through `timetoalign`, heavy computation, and exports, while the browser keeps a small editing core. This division keeps Python library capabilities close to the operations that need them and keeps interaction responsive without a per-keystroke network request.

## What exists today and what is planned

`tilie-server` starts a FastAPI server on loopback, serves the built editor, and answers authenticated `GET /api/health`. The editor is a header and the canvas, which fills the rest of the page, with an inspector drawer on the right. It opens, saves, imports and exports files, autosaves in the browser, and inspects and edits the selected block's manifest ([The editor](#the-editor)); everything it changes goes through the commands of `core`.

Of the six workspace packages, `core` implements the three layers: exact numbers, validated manifest load (all three file kinds, every supported schema version, migrated to 0.7.0) and save (0.7.0), the immutable workspace view with its blocks, ids and order, the four commands over addresses, a store with its command journal, and the workspace file ([The core package](#the-core-package)). `layout` derives a drawing from a manifest, placement, style layers, and font metrics; `writers` turns a drawing into element descriptors and writes placed drawings as SVG or TikZ ([Layout and writers](#layout-and-writers)). `arranger` shows a workspace on a canvas and turns every completed gesture into one command ([The canvas](#the-canvas)). `editor` mounts the canvas on one store, opens and saves files, inspects manifests, and autosaves a workspace's text in IndexedDB ([The editor](#the-editor), [Autosave](#autosave)). `client` only establishes its export, strict type checks, dependency boundaries, and tests.

Loading sources through the server, raster exports, generated API clients, collaboration over a network, and automation endpoints are not implemented. Except for the packages, the canvas and the editor described as built, the remaining sections describe the intended architecture so additions have explicit boundaries; they do not describe current behavior as available functionality.

## The canvas

The canvas is a data-driven renderer hosted by a diagram engine. It has two levels. At the workspace level, blocks are placed freely: drag, snap, selection, pan, zoom, resize and z-order. A block draws one manifest of any of the three file kinds.

At the block level, the drawing comes from the manifest rather than from an editable drawing surface. Every file is drawn the same way, as a bundle: a grey box that opens with the bundle's title in a bundle file; each group a **frame**, a rounded rectangle holding the group's title and its members' cards one under the other in display order; and each timeline drawn as a root (a group's member, a bundle's ungrouped root, or a timeline file's timeline) in its own **card**, a raised rounded rectangle with a shadow offset to the right and down. All drawn roots share one graphical length and one start, so they begin and end at the same x. Within its card, `draw` maps time to x through the placement's graphical length, applies its vertical spacing and requested box size, lays out children, regions and flow control in bands and rows in the placement's band order, and stacks each timeline's conversion maps against its own line. A segment line draws its segments on its own line, separated by boundaries. A top-level timeline ends with an arrowhead (an open one for a segment line), or with a filled circle when it is locked; a child ends with an open diamond. A member that is a child timeline also draws its ancestors above its line as **ancestor lines**, clipped to the member: where an ancestor reaches beyond the member's start or end, its line runs on into a double chevron, and two marks label the member's start and end on the ancestor's axis. So one timeline may be drawn more than once, as an ancestor line of several members or also as a member. A placed drawing has a canvas position and a uniform scale. A person edits the underlying manifest through commands, never by dragging an arrow endpoint. This preserves the meaning of a musical relation independently of a particular display.

`@timetoalign/tilie-arranger` builds the workspace level on [Svelte Flow](https://svelteflow.dev) (`@xyflow/svelte`), which supplies pan and zoom, node dragging, the selection rectangle, keyboard focus and culling ([decisions/0020](../decisions/0020-svelte-flow.md)). No other package imports it. The arranger's plain TypeScript (`project`, `snap`, `resize` and the gesture commands) holds every rule below and is tested without a browser; its Svelte components (`Canvas`, `BlockNode`, `CanvasToolbar`, `ResizeToolbar`, `SnapGuides`) connect those functions to Svelte Flow.

### One node per block

`project(view, selection, previous, metrics)` returns one Svelte Flow node per block, in index order. A node's id is the block id; its `position` is the block's `x` and `y`; its `width` and `height` are the drawing's box times the block's scale, given again as `measured`, with `handles: []`, so the node is complete and Svelte Flow never measures it. A node that Svelte Flow has to measure is mounted even when it lies outside the view, which would defeat culling. `selected` says whether the block id is in the selection, `zIndex` is the block's rank among its siblings by `index`, and `data` carries the block, its drawing, the drawing's descriptors, the ids of its selected elements and whether it holds any. A node of `previous` whose block, drawing, position, rank and selection are unchanged is returned as the same object, and Svelte Flow skips an object it has already adopted; a change to one block re-renders one node.

`drawingOf(block, settings, metrics)` draws a block with the layers `DEFAULT_LAYER`, the workspace's `graphical` and the manifest's own `graphical`. Blocks are immutable, so the drawing is memoized per block object and recomputed only when the settings or the metrics change identity; the descriptors are memoized per drawing. Neither is stored in the workspace or the file.

`BlockNode` renders the descriptors as Svelte elements inside one `<svg>` per node, whose `viewBox` is the drawing's box and whose size is that box times the scale. Every attribute is the text the SVG writer writes, so the node's element tree equals the exported SVG's, element for element. Text is rendered as text, never parsed as markup: names and labels are user data. Every drawn element carries its address in `data-address`, every drawing of an element drawn more than once included. While the pointer is over a block, the card under it is marked with `data-hovered`, a soft glow that shows which timeline a press selects; a segment boundary under the pointer is marked too, drawn in the accent colour (`hover.ts`). The marks act on nothing and are never stored. The drawings use the DejaVu Sans file bundled by timeskeleton, declared under a family name of its own so that a system copy never stands in for it, and they are mounted only once that face has loaded.

### Preview during a gesture, one command at its end

The canvas follows the store with a `$state.raw` view refreshed by the store's `subscribe`. Its nodes are a writable `$derived` of the view, the selection and the resize preview, bound to Svelte Flow with `bind:nodes`. During a drag Svelte Flow writes the dragged positions into that value, and nothing else runs. On release the arranger builds one command, the store applies it, and the view's change derives the nodes again, replacing the preview with the stored positions. A gesture that stores nothing restores the projection. Undo and redo are exact, because the canvas shows nothing between two commands that the next command does not either store or discard.

- A drag of n blocks is one `set` with n changes `{x, y}`.
- A keyboard move (an arrow key moves the selected blocks one grid step, Shift and an arrow key eight) is one `set`.
- A resize is one `set` on its block.
- A change of order is one `set` of `index` (see below).
- Delete is one `remove`.

### Numbers on the canvas

Canvas numbers are doubles, and the positions Svelte Flow reports carry binary noise. Before a number is stored it is quantized: a position to the grid when the workspace snaps to its grid, every other number (and every position when the grid does not snap) to 1/2048 unit. 2048 is the bundled font's units per em, so at an integral font size and scale every text-derived edge and plot origin is a multiple of 1/2048, and a position aligned to one is stored exactly.

While a block is dragged, Svelte Flow snaps it to the grid (`snapGrid`). The arranger then aligns the dragged block horizontally: its left edge or its plot origin (the canvas x of the start of its root's line) moves onto the nearest left edge or plot origin of another block lying within 6 screen pixels, and a vertical guide line is drawn there for as long as the alignment holds. The other dragged blocks move by the same offset. Svelte Flow has no alignment guides of its own.

### Resizing

A block is resized in one of three modes, each changing a different input of its drawing:

- **Scale** sets `scale`: everything grows or shrinks with its proportions, text included. Only the four corner handles are offered; the new scale is the larger of the two axis ratios, never below 1/8.
- **Box** sets `width` and `height`: the box changes and the content keeps its place at the top left. A request at or below the content's own extent stores `null`, so the box follows the content when it later grows.
- **Stretch** sets `length` from the left and right handles, `spacing` from the top and bottom ones and both from a corner: lengths and distances stretch, while markers, line widths and text keep their size. The content's width grows with `length` and its height with `spacing` in piecewise-linear steps, as timeskeleton's drawing specification derives them, so the values that put the dragged edge under the pointer are solved for numerically. The floors are 8 for `length` and 1/4 for `spacing`.

In every mode the dragged edge ends under the pointer, the opposite edge stays put, and a left or top handle also stores the block's new `x` or `y`. While the pointer is down, the block is drawn at the previewed values, so the preview is exactly what the command will store.

When exactly one block is selected, a toolbar above it (Svelte Flow's `NodeToolbar`) offers the modes as three buttons, Scale, Box and Stretch; the keys 1, 2 and 3 choose them too. The pressed button shows its mode's handles: four corners for Scale, eight handles for Box and Stretch. The mode is the viewer's own and stays when the selection changes. The handles are the arranger's own elements rather than Svelte Flow's resize controls, because a block's size during a resize is whatever its drawing measures at the previewed placement; the pointer only provides a distance in canvas units.

### Selection, marquee and deletion

The selection is a set of addresses: block ids and `<block>/<element address>` ([Ids, addresses and order](#ids-addresses-and-order)). It alone decides which blocks the canvas shows as selected; Svelte Flow's own selection flags are reset to it after every click and selection rectangle. A selected address is marked at every place it is drawn, so selecting a timeline drawn both as an ancestor line and as a member marks both lines.

- A click on a drawn element selects that element only, found by the nearest `data-address` around the click. Its block then shows a dashed outline.
- A click on a timeline's card, or on its shadow, selects that timeline.
- A click on a block's background selects the block.
- Shift and a click add the address to the selection, or remove it when it is selected.
- A click on the empty canvas clears the selection, blocks and elements, in either mode; Shift and a click there leave it as it is. A press whose pointer moves at most 4 px before it is released is still a click (Svelte Flow's `paneClickDistance`), so a tap or a trackpad click that moves slightly never becomes an empty selection rectangle.
- Escape cancels a resize in progress and restores the block's stored values; only when no resize is running does it clear the selection.
- A focused block is selected with Enter or Space.
- A drag that starts anywhere on a block, on one of its elements included, moves the block. A drag on a block that is not selected, and holds no selected element, first selects that block alone.

A plain drag on the empty canvas pans. Shift and a drag draw a selection rectangle instead, which replaces the selection with exactly the blocks lying wholly inside it.

The Marquee button of the canvas controls (accessible name "Add to selection (marquee)") switches to an additive mode, which is also how a touch screen selects several items. While it is pressed, a drag on the empty canvas draws a selection rectangle instead of panning, and the blocks wholly inside it are added to the selection. Every click, Enter or Space adds its address, or removes it when it is already selected, as Shift does outside the mode. A click on the empty canvas still clears the selection; the end of a selection rectangle is no click.

Delete or Backspace removes exactly the selected addresses as one `remove`, blocks and elements mixed. A selected part of an element, such as its name or its label, stands for the element. While elements are selected, the elements a Delete would take with them (the descendants of a selected timeline and everything they hold) are marked with `data-affected`. A selection that holds the root timeline of a timeline file's block is refused whole, because a root goes only with its block, and so is a selection holding a timeline, a group or the bundle of a group or bundle block, which cannot be removed yet; the canvas shows why in a status region that screen readers announce, for a root with the advice to select the block.

### Order

The order of blocks is their `index`, a fractional index among siblings, and it is projected as the nodes' `zIndex`; selecting a block does not raise it. Ctrl and `]` (Cmd on macOS) move the selected blocks one place forward past the next unselected block, Ctrl and `[` one place backward, and with Shift to the front or the back. Only the moved blocks receive new indices, each between its new neighbours.

### Keys

The canvas reads its keys before Svelte Flow does, so that a key is handled once; keys typed into a text field are left alone. The canvas is one tab stop (an ARIA `application` named "Arranger"); it takes the focus when the editor opens, when a workspace is opened, and when it is pressed. Its keys apply only while the focus lies on the canvas or inside it, so a key pressed with the focus on the page's body, the header or the inspector does nothing on the canvas. Undo, redo and the file shortcuts are the page's, not the canvas's ([The editor](#the-editor)); they are listed here because they work on the canvas too.

| Key | Action |
| --- | --- |
| Tab, Enter or Space | Focus a block, select the focused block |
| Wheel, Shift and the wheel | Pan vertically, pan horizontally |
| Ctrl and the wheel (Cmd on macOS), a pinch | Zoom |
| Arrow keys, Shift and an arrow key | Move the selected blocks one grid step, eight grid steps |
| Delete, Backspace | Remove the selected addresses |
| `+`, `-`, `0` | Zoom in, zoom out, fit every block into view |
| Ctrl+Z; Ctrl+Shift+Z or Ctrl+Y (Cmd+Z, Cmd+Shift+Z on macOS) | Undo, redo |
| Ctrl+`]`, Ctrl+`[`, with Shift | Forward, backward; front, back |
| 1, 2, 3 | Resize mode Scale, Box, Stretch |
| L | Lock or unlock the canvas |
| Escape | Cancel a resize in progress; otherwise clear the selection |

Svelte Flow pans on the wheel (`panOnScroll`) and zooms only with Ctrl or Cmd held (`zoomActivationKey`); a touchpad pinch, which browsers report as a wheel event with Ctrl, zooms too, and so does a two-finger pinch on a touch screen. Outside macOS, Chromium and Firefox already report a Shift wheel as horizontal travel, which Svelte Flow would discard while converting vertical travel; the canvas pans such an event horizontally itself, at Svelte Flow's speed (half a pixel per pixel of travel, a line counted as 20 pixels).

### The lock

The Lock button of the canvas controls, or L, locks the canvas. A locked canvas changes no placement: a drag on a block pans the canvas instead of moving the block, the arrow keys move nothing, the resize handles are hidden and the mode buttons are disabled. Selecting, deleting, reordering, panning and zooming stay available.

### Overlays and culling

The resize handles and the alignment guides lie in one overlay layer, Svelte Flow's viewport portal in front of the nodes, stacked above any block; they scale inversely with the zoom so that they keep their screen size. The canvas controls (zoom in, zoom out, fit, Lock, Marquee) are a vertical stack of icon buttons at the bottom left of the canvas, Svelte Flow's controls panel holding the editor's own buttons; each has an accessible name and a tooltip naming its key, and the stack is one toolbar whose buttons the Up and Down arrow keys move between.

Above 500 blocks only the blocks in view are mounted (Svelte Flow's `onlyRenderVisibleElements`); a block partly in view is mounted whole. Below that count culling costs more than it saves, as the measurements in [Performance](#performance) show.

### Per-viewer state

The selection, the viewport, the lock and the resize mode belong to the person viewing the canvas: the editor holds them, and they are never stored in the workspace or its file, so a text diff of two workspace files shows only real changes. A newly opened workspace is fitted into view. Svelte Flow's attribution link is hidden (`proOptions.hideAttribution`, which its MIT licence permits); the editor's About dialog credits it instead.

## The editor

`@timetoalign/tilie-editor` is the application around the canvas. Every change it makes to a workspace is a command dispatched to the store, so undo, redo, the journal and the autosave cover it as they cover a gesture.

### The header and the File menu

The header holds the title, the File menu, the open file's name, a quiet "offline" mark while the server's health check fails (its reason in the mark's tooltip and in text for screen readers), and the About button. The file name, and the page's title, start with `•` while the workspace has changes it was not opened or saved with; undoing back to the saved state removes the mark.

The File menu is a WAI-ARIA menu button: Enter, Space or the down arrow open it on its first item, the up arrow on its last; the arrows, Home and End move between the items, and Escape closes it.

| Item | Shortcut | Action |
| --- | --- | --- |
| New workspace | | An empty workspace named `untitled.tle.json` |
| Open… | Ctrl+O (Cmd+O) | A `.tle.json` file, read with `readWorkspace` into a new store |
| Save | Ctrl+S (Cmd+S) | The workspace written with `writeWorkspace`, back into the file it was opened from or last saved to |
| Save as… | Ctrl+Shift+S (Shift+Cmd+S) | The same, into a file chosen now |
| Import manifest… | | A timeline, group or bundle file, read with `loadManifest`, added as one `add` whose block's top-left lies at the centre of the visible canvas, snapped to the grid; the new block is selected and the view does not move |
| Export manifest… | | The manifest of the block the selection lies in, written with `saveManifest` as `<id>.json`, the id of a timeline file's root timeline, a group file's group or a bundle file's bundle; disabled unless the selection lies in exactly one block |

Where the browser has the File System Access API, the editor opens and saves through its pickers and keeps the file's handle, so Save writes back without asking again. Elsewhere it opens through a file input and saves by downloading the file under its name ([decisions/0023](../decisions/0023-file-access-written-in-editor.md)). A cancelled picker does nothing. New workspace and Open… on a workspace with unsaved changes first ask whether to discard them, with Cancel focused. A file that cannot be read leaves the open workspace as it is and shows a dismissible message listing the reader's problems, each with the JSON pointer of its place in the file; editing goes on while messages are shown.

The file shortcuts and undo and redo work wherever the focus is outside a dialog; undo and redo leave a text field to the browser's own undo. After an undo or a redo, the addresses of the selection that no longer exist are dropped.

### The inspector

The inspector drawer opens from the `«` tab at the canvas's right edge and closes with its `»` button; the browser remembers whether it was open. It shows the block the whole selection lies in.

- **Properties.** A form for the block's `x`, `y`, `scale`, `length`, `spacing`, `width` and `height`. Each field shows its value rounded to at most two decimals; the stored value keeps every digit until a new one is committed. Typed text is applied as one `set` on Enter or when the field loses the focus, and Escape discards it; an empty `width` or `height` is `null`, the content's own size. A step, with a spin button, the Up and Down arrow keys or a wheel turn over the focused field, is applied at once as one `set` of its own: it adds or subtracts 1 for `x`, `y`, `length`, `width` and `height` and 0.1 for `scale` and `spacing`, starting from the exact stored value, never from the rounded text (from the typed text when there is some; an empty field counts as 0). The result is the exact decimal one: 1 − 0.1 gives 0.9, and 0.2 + 0.1 gives 0.3 rather than the binary sum 0.30000000000000004. While a block is dragged or resized, its fields follow the gesture, showing the values the canvas previews; the store changes only on release, and the fields then show the stored values. Text being typed is never replaced. A refused value is shown beside its field.
- **The manifest as text.** The manifest in JSON (timeskeleton's standard writer), YAML or TOML, chosen by three radio buttons; YAML ([decisions/0024](../decisions/0024-yaml-library.md)) and TOML ([decisions/0025](../decisions/0025-toml-library.md)) are loaded the first time they are chosen. Numbers stay exact in all three: integers of any size, and integral floats, which the text writes as `2.0`. Apply, or Ctrl+Enter (Cmd+Enter) in the text, reads the text and dispatches one `set` replacing the block's manifest; the store's checks decide. A refused text stays as typed, and its problems are listed: a syntax error at its line and column, any other problem at the JSON pointer of its member in the manifest. Revert shows the manifest again. While the same block stays selected, an applied YAML or TOML text is patched in place rather than rewritten, so comments typed into it are kept.
- **Unapplied edits.** While the text holds an edit, the format and the styling toggle cannot be changed, and a change of the manifest from elsewhere (a gesture, an undo) does not replace the text; a notice says that the manifest changed and Revert shows it.
- **Show styling.** Off by default, it hides the manifest's `graphical` block from the text; applying a text then keeps the block's styling as it is, and a `graphical` member typed into the hidden text is refused rather than dropped.
- **TOML and null.** TOML has no null. A member that the manifest's schema requires and allows to be null is left out of the TOML text when it is null and read back as null when it is missing; in schema 0.7.0 these are `name`, `measure_map` and `metric_hierarchy` of a timeline, `name`, `source_unit` and `target_unit` of a conversion map, `name` of a region and of a marker, `name` and `label` of a break, `target` and `label` of a jump, and `name` of a group and of a bundle. They are found by walking the schema document of the manifest's file kind along the value, following references into the version's other documents (from 0.7.0 on `core`, `timeline`, `group` and `bundle`). A manifest holding any other null, such as a measure-map row's optional `nominal_length`, cannot be shown as TOML, and the inspector names that null's path.

### About

The About dialog shows the editor's version, the server's name and version with its `timetoalign` version (or "offline" with the reason), the timeskeleton package and schema version, the workspace packages, and the third-party software in the bundle with its licence and copyright lines. `vite build` writes `THIRD_PARTY_NOTICES.txt` beside the built page with the full licence text of every bundled npm package, of the canvas control icons copied from Svelte Flow, and of the DejaVu Sans font; the dialog links to it, and the wheel ships it with the app.

## Exact values and commands

Exact rationals remain exact while positions are carried to the root timeline's axis. A coordinate is one atomic value, `{ unit, number_type, value }`, never a container of separately editable parts; its value is a JSON integer, a JSON number or a `[numerator, denominator]` Fraction pair as the number type selects, following the BOPP core primitives. Layout converts a root-axis proportion to a double once and performs the remaining canvas arithmetic as binary64 in the order the drawing specification gives. The writers round the exact value of each resulting double to four decimal places, ties to even, when they serialize it. Canvas quantities of a block (position, scale, length, spacing, box size) are plain finite numbers: they place a drawing and carry no musical meaning.

Every edit is a serializable, validated command carrying its author and time. Commands are the single entry point for the UI, tests, and automation. Before applying an edit, command handling checks invariants such as containment, number type, and unit. The schema validates a manifest on load, on save, and whenever a command brings one into a block.

The workspace is a plain immutable value, changed only by applying a command. The store keeps every command it applies in a journal, which is saved in the workspace file beside the workspace it produced; replaying the journal reproduces the workspace, and the journal is also the undo history. Event tables remain outside the manifest and move as Arrow data rather than being embedded in TimeSkeleton.

## The core package

`@timetoalign/tilie-core` is framework-free: no DOM, no Svelte, no network. Its one entry point holds the numbers, the manifest types, the file kinds (`manifestKind`, `manifestRoots`, `memberDrawings`, `elementAddress`, `elementOf`), `loadManifest`, `saveManifest` and `checkManifest`, the workspace view and blocks, ids and order keys, `parseCommand` and `apply`, the store and `replay`, `readWorkspace` and `writeWorkspace`, and the error types. The package needs Node 22.18 or later, as `@timetoalign/timeskeleton` does.

### Numbers

`Rational` is an exact fraction over `BigInt`, always normalized (positive denominator, lowest terms), with exact addition, subtraction, multiplication, division and `floor`. It is built from a `[numerator, denominator]` pair, a `bigint`, a safe integer or a decimal integer string, and never from a JavaScript float: `0.5` and `2 ** 53` are refused. A `Real` is a value as Python's numeric tower holds it, an exact `Rational` or a float; `addReal` and `compareReal` combine and compare such values as the tower does (a sum involving a float is a float, a comparison is exact), and `realOf` reads a coordinate's value as one. `fromFloat` returns the exact binary value of a float, as Python's `Fraction(float)` does, and `toFloat` the double nearest to a `Rational`; `fromFloat` serves arithmetic that must be exact on a float's value, such as the writers' page transform, and never re-expresses a coordinate. A `Coordinate` is `{unit, numberType, value}` whose value is what the axis's number type declares: a `bigint` for `int`, a `number` for `float`, a `Rational` for `fraction`. `coordinateFromDict` and `coordinateToDict` mirror timetoalign's `coordinate_from_dict` and `coordinate_to_dict`: an `int` axis reads a JSON integer, or an integral JSON number as that integer; a `float` axis reads a JSON number, or an integer as the float it equals exactly; a `fraction` axis reads only a pair; every integer is int64-bounded. Arithmetic and comparison (`addCoordinates`, `subtractCoordinates`, `compareCoordinates`, `coordinatesEqual`) work within one axis only, and throw `AxisMismatchError` across units or number types.

### The manifest value

A loaded manifest is exactly the value `@timetoalign/timeskeleton`'s `parse` returns for a valid 0.7.0 manifest, typed member by member: `Manifest` is one of `TimelineFile`, `GroupFile` and `BundleFile`, `manifestKind` tells which, and every timeline in it is a `TimelineManifest`; the optional `graphical` block of styles and statements is included. `manifestRoots` lists a file's root timelines (a timeline file's `timeline`, or each of `timelines`), and `memberDrawings` what its drawing draws as roots: each group's members in display order, each with its ancestors, then a bundle's ungrouped roots. Every number in it is a `JsonNumber`: a plain `number` for a safe integer or a float with a fractional part, a `bigint` for an integer beyond 2^53, and a `JsonFloat` for an integral float, so that `600.0` stays a float and is written back as `600.0`. A command that carries a float whose value is an integer passes it as a `JsonFloat`. `core` reads, orders and writes no JSON of its own: reading, the canonical order and the standard writer, which sorts every object's keys by code point, are the schema package's.

### Load and save

`loadManifest(text)` reads the text with `parse`, which accepts a manifest valid against the schema of the version it declares, 0.5.0, 0.6.0 or 0.7.0 (group and bundle files exist from 0.7.0 on); migrates it to 0.7.0 with timeskeleton's `migrate`; and then checks every invariant, root by root. A manifest that reaches core any other way, in a workspace file or a command, is migrated the same way, so every manifest core holds and writes is 0.7.0. It returns the manifest in canonical order, or a `LoadError` whose `problems` list `invalid_json` for text that is not JSON, the first `schema_violation` with the path the shared validator reports, or every invariant violation of a schema-valid manifest. `saveManifest(manifest)` validates the manifest and checks its invariants, throwing `InvalidManifestError` with every problem, and writes it with the schema package's `dumps`: canonical order, the standard text, byte-identical to what the Python writer produces. Every 0.7.0 manifest fixture of the schema package, timeline, group and bundle files alike, loads and saves to its own bytes, and every timeline fixture of 0.5.0 and 0.6.0 loads and saves as timeskeleton's migration writes it.

### Commands

Every edit is a command, a plain JSON object `{type, ...}`, and there are four: `add`, `set`, `remove` and `style`. Each is aimed at addresses, and the kind of its target decides what it does. `apply(view, command)` is a pure reducer: it never modifies its input and returns either the new view or a `CommandError` `{code, message, path}`.

- `add {into, <kind>: value}` adds a `block` into `workspace`, or a `child`, `region`, `break`, `jump`, `marker` or `map` into a timeline's address. The value carries its id.
- `set {changes: [{target, values: {...properties}}]}` sets properties of blocks and elements; the properties are nested under `values`, so none of them (such as a jump's `target`) collides with the change's `target`. One gesture is one command, so moving five blocks is one `set` with five changes.
- `remove {targets}` removes blocks and elements, mixed; a block goes with every block whose `parent` chain reaches it, and a child timeline with its subtree.
- `style {select, set, name?, blocks?}` puts a style statement into the manifest of each listed block, or of every block with an element the selector matches when none is listed. With `name`, the declaration becomes a named style in that manifest's `styles`. A statement whose selector equals an existing one is merged into it; a property set to `null` is removed, and a statement left empty is dropped.

What each target admits:

| Target | Address | `set` | `add` into it | `remove` |
| --- | --- | --- | --- | --- |
| workspace | `workspace` | `grid {size, snap}`, `blockDefaults {scale, length, spacing, width, height, order}`, `graphical` (the default statements) | `block` | no |
| block | `<block>` | `x`, `y`, `index`, `scale`, `length`, `spacing`, `width`, `height`, `order`, `manifest` (whole) | none | yes |
| timeline (root or child) | `<block>/<id>` | `name`, `length`, `locked`, `meta`; a child also `offset` | `child`, `region`, `break`, `jump`, `marker`, `map` | a child yes; the root no (remove the block) |
| region | `<block>/<id>` | `name`, `start`, `end`, `meta` | none | yes |
| break | `<block>/<id>` | `coordinate`, `control_type`, `condition`, `repeat_count`, `label`, `name`, `meta` | none | yes |
| jump | `<block>/<id>` | `from_coordinate`, `to_coordinate`, `control_type`, `condition`, `repeat_count`, `label`, `meta`, and `target` (a marker id of the same timeline, or `null`) | none | yes |
| marker | `<block>/<id>` | `name`, `coordinate` | none | yes |
| conversion map | `<block>/<id>` | `map` (the payload, whole, its `id` unchanged) | none | yes |

In a group or bundle block a timeline keeps its bare address `<block>/<id>`, and a region, break, jump, marker or conversion map is addressed as `<block>/<root>/<id>`, `<root>` being the root timeline whose tree holds it. There a group and the bundle are not targets of commands (`unknown_target`), and `remove` refuses a timeline, root or child, with `unsupported_target`: removing it is not supported yet.

A command is atomic: one refused change refuses it whole. Ids are never settable. A timeline's `class`, `unit` and `number_type`, its `measure_map` and its `metric_hierarchy` are not settable. Canvas numbers are doubles; positions of elements are coordinate dicts. The three ways of resizing a drawing are gestures that set different block properties, not commands. The caller mints the id of what it adds, so that replaying a journal is deterministic: a block id as described below, an element id with `nextId(view, block, prefix, into?)`, the smallest `{prefix}_{N}` that a new element may carry: in a timeline file one no id of the manifest uses; in a group or bundle file one no id of the tree it goes into (the tree holding the timeline `into`) and no group or bundle id uses, and for a new timeline also no timeline id of the file. An id already held in that scope is refused with `duplicate_id`.

`parseCommand(value)` reads a command from any value, as a user interface or an agent sends it, and `dispatch` and `apply` read every command through it. A refusal's path starts with the address of the target at fault, followed by the property or kind at fault (`[<address>, "length"]`), or by `"manifest"` and a location in the manifest the command would leave; only a malformed command, which has no target, names the malformed member of the command itself. The codes are stable strings, exported as `ErrorCode`:

- reading: `invalid_json`, `invalid_command`, `invalid_coordinate`, `invalid_value`, `schema_violation`;
- the workspace file: `unsupported_format`, `unsupported_version`, `unknown_member`, `missing_member`;
- the workspace: `invalid_block_id`, `block_kind_mismatch`, `unknown_parent`, `parent_cycle`, `invalid_index`, `duplicate_index`, `non_finite_number`, `non_positive_number`, `invalid_order`;
- addressing: `invalid_address`, `unknown_target`, `unknown_property`, `wrong_target_kind`, `id_not_settable`, `not_removable`, `unsupported_target`, `duplicate_id`;
- manifest invariants: `unit_not_allowed`, `number_type_not_allowed`, `off_axis`, `child_unit_mismatch`, `negative_offset`, `child_exceeds_parent`, `child_not_locked`, `locked`, `length_below_content`, `region_end_before_start`, `map_source_unit_mismatch`, `metric_hierarchy_without_measure_map`, `key_mismatch`.

### Invariants

The manifest invariants are timetoalign's, checked twice: by `checkManifest` over a loaded manifest and by every command over the manifest it would leave. A class admits its units and a unit its number types; a child has its parent's unit and a non-negative offset, ends within its parent, and is locked when placed; a locked timeline's length cannot be set, and no length falls below the end of a child; a region does not end before it starts; a map's source unit is the timeline's unit; a metric hierarchy needs a measure map. A child placed past the end of an unlocked parent lengthens the parent to the child's end; a locked parent refuses. The catalogue in `app/packages/core/tests/README.md` lists every row. In a group or bundle file every root's tree is checked in turn. That ids are unique in their scope (the whole manifest in a timeline file; in a group or bundle file the file for timelines, groups and the bundle and the root's tree for every other element), whatever the kinds of the elements carrying them, and that a jump's `target` names a marker of its timeline, are timeskeleton's identity rules, checked by its validator together with the schema; names are for display and may repeat.

Four rules go beyond what the library enforces, because the editor addresses and stores values directly and refuses a manifest the library would not have written: a child stored under a key has that key as its id, a loaded child is locked (the library writes every child with `locked: true` and would silently lock one that is not), a coordinate of a region or of flow control must already carry the axis's number type (the library would re-express it), and a parent grows only to a value its own number type holds exactly (an `int` parent cannot grow to 9/2, a `float` parent cannot grow to 1/3). What the library does not enforce, `core` does not invent: a region, break, jump or marker may lie outside its timeline, and any number of breaks or jumps may share a coordinate.

A child shares its parent's unit but may have another number type. Its end, offset plus length, and every comparison against it follow Python's numeric tower: an `int` and a Fraction are exact, a sum with a float is a float with each exact operand correctly rounded first, and a float compares with an exact value exactly.

### The workspace view

A workspace is held as a `View`, an immutable plain value: `meta` (`format: "tilie-workspace"`, `version: 1`), `settings` and `blocks`, a map from block id to block. The settings are `grid {size, snap}`, `blockDefaults` (scale 1, length 400, spacing 1, no requested box size, the band order `children`, `regions`, `flow`) and `graphical`, the workspace's default style statements, empty by default; the grid is 8 units with snapping.

A block has an `id`; a `blockKind`, `timeline`, `group` or `bundle`, which must equal its manifest's file kind, the top-level member beside `meta`; a `parent`, the canvas group holding it, `null` in this version and never a timeline group, which lives in a manifest; an `index`, its order key among the blocks of the same parent; and exactly the inputs of its drawing besides the manifest's own: `x`, `y`, `scale`, `length`, `spacing`, `width` and `height` (each `null` for the content's own size), `order` (a permutation of `children`, `regions` and `flow`) and `manifest`. `checkWorkspace(view)` returns every problem of a view, by block id: a block stored under another key, a malformed id, a block kind that differs from its manifest, a missing parent, a cycle of parents, a malformed order key or one shared with a sibling, a canvas number that is not finite, a block scale, length, spacing, width or height that is not positive, a band order that is not a permutation of the three groups, and every schema or invariant problem of a block's manifest.

### Ids, addresses and order

A block id is ten characters from `0-9a-z`, drawn from the platform's cryptographic random source, rejecting bytes that would bias the alphabet. Block ids are the workspace's namespace. An address is `workspace`, a block id, or a block id followed by `/` and the address of an element of that block's manifest (`elementAddress`). In a timeline file an element's address is its id. In a group or bundle file a timeline, a group and the bundle keep their bare ids, and every other element is addressed as `<root>/<id>`, `<root>` being the root timeline whose tree holds it, also when a member below that root is drawn as a root of its own. A drawn part of an element appends `/start` or `/end` (the root's wedges, a member's marks on its ancestor lines, a segment's boundary at `/start`), `/name`, `/label` or `/card` to the element's address, as timeskeleton's drawing specification addresses it in the descriptors; in a group or bundle file no map, region, break, jump or marker may carry one of these words as its id, so `elementOf` reads every address without ambiguity. A block id holds no `/`, so the first `/` splits an address (`parseAddress`, `formatAddress`); `mintBlockId()` draws a block id and `manifestIds(manifest)` lists the address of every element of a manifest. Element ids live inside a manifest, unique in their scope there and freely repeated across blocks; the id a manifest carries is the id, and `nextId` mints `{prefix}_{N}` (`clt_1`, `region_1`, `break_2`) only for an element that has none, following timetoalign's scheme.

Sibling order is a fractional index: a string key that compares with ordinary string comparison, so that a block moves between two others by taking a key between theirs, without renumbering. `indexBetween(a, b)` returns one key strictly between two keys (`null` for an open end), `indicesBetween(a, b, n)` returns `n` increasing keys, and `isIndex(key)` validates one. Keys are compatible with those of Rocicorp's `fractional-indexing` 4.0.0, written in `core` ([decisions/0016](../decisions/0016-fractional-indexing.md)).

### The store and its journal

`createStore(workspace, {author?, clock?})` holds a workspace and returns `view`, `journal`, `dispatch(command)`, `undo()`, `redo()`, `canUndo`, `canRedo`, `setAuthor(name)` and `subscribe(listener)`, which returns a function that unsubscribes. `dispatch` stamps the command with its author (by default `Gerhardt`) and its time (ISO 8601, UTC, from the injected clock), applies it with the pure `apply`, and appends the entry `{command, author, time}` to the journal; it returns `null`, or the `CommandError` of a refused command, which leaves the store unchanged. The journal is the undo history: `undo` moves its last entry to a redo stack kept in memory, `redo` moves it back, and a new command clears the redo stack. `replay(journal)` applies a journal from the empty workspace and returns every view on the way; the last has the workspace's settings and blocks, so undo reaches back across sessions. Views of the current session are kept with structural sharing, and the first undo past the session's start replays the journal once to recover the earlier views. The store's decision record is [decisions/0019](../decisions/0019-workspace-store-and-journal.md).

### The workspace file

A workspace is saved as one JSON file, `<name>.tle.json`: `{meta, settings, blocks, journal}`, with every manifest embedded whole. It holds the blocks, never the canvas engine's own state, so a text diff of two files shows only real changes. `writeWorkspace(workspace)` writes a `Workspace`, `{view, journal}`, with timeskeleton's standard writer `dumps`, which sorts the keys of every object by code point. `readWorkspace(text)` reads it with timeskeleton's lossless `parseJson` and returns the `Workspace` or a `LoadError` listing every problem; it refuses another `format` (`unsupported_format`), another `version` (`unsupported_version`), any unknown or missing member, any malformed block or journal entry, and any manifest that fails the schema or an invariant, at its path in the file. This is version 1 of the format, and there is no migration code. `writeWorkspace(readWorkspace(text))` returns the text it read, byte for byte. `core` is the one implementation of the format; other programs read the file as plain JSON, and a block's manifest is a TimeSkeleton manifest that timetoalign reads with `Timeline.from_dict`, `TimelineGroup.from_dict` or `AlignmentBundle.from_dict`, as its file kind requires.

### Autosave

The `editor` package keeps the last text of each workspace in the browser's IndexedDB, one slot per workspace key ([decisions/0018](../decisions/0018-indexeddb-autosave.md)). The editor uses one slot, whichever workspace is open: every change is written one second after the last, and a pending write is made at once when the page is hidden or the editor goes away. When the editor opens and the slot holds anything but an empty new workspace, it asks "Restore the unsaved workspace from …?", with the time of the workspace's last journal entry; Restore opens it, untitled and marked unsaved, and Discard empties the slot. A failing autosave is reported once, in a message, and editing goes on. `createAutosave({key, delayMs})` returns `schedule(text)`, which writes the text once no further text was scheduled for `delayMs`, and `flush()`, which writes the pending text now and waits for every write; `recoverWorkspace(key)` returns the last written text or `null`, and `clear(key)` empties a slot. The autosave stores the text `writeWorkspace` returns and never parses it. A storage failure reaches the caller as a promise rejected with an `AutosaveError` whose `code` is `indexeddb_unavailable` or `indexeddb_failed`.

## The schema contract

`@timetoalign/timeskeleton` supplies the generated types, the validator of every supported schema version (from 0.7.0 on four schema documents per version: `core`, `timeline`, `group` and `bundle`), `migrate`, standard writer, the manifest fixtures, drawing font and font metrics. The schema repository, not TiLiE, is the source of truth. Every application package takes schema 0.7.0 through a `link:` dependency on the `js/` package of a timeskeleton checkout lying beside this repository (`../timeskeleton/js` from its root), built there with `pnpm install` and `pnpm build`. The `timetoalign` library proves conformance in its own tests. TiLiE consumes that contract, preserving exact values and invoking validation at the manifest boundaries.

## Layout and writers

The drawing of a manifest is specified in the schema repository, not here: timeskeleton's [drawing specification](https://github.com/TimeToAlign/timeskeleton/blob/main/docs/drawing.md) defines the `graphical` block, arithmetic, default styles, font, layout, element descriptors, page, and SVG and TikZ profiles completely enough that another implementation writes the same text byte for byte. The specification, together with the SVG and TikZ fixtures of a schema version, pins the drawing. A drawing is derived and is not exchanged as JSON; there is no drawing schema.

`@timetoalign/tilie-layout` exports `draw(manifest, placement, layers, metrics)`, a pure deterministic function implementing sections 1 to 8 of the specification for every file kind. The placement supplies the graphical length all drawn roots share, the vertical spacing, the requested box size, and the band order. The layers are the ordered `Graphical` blocks of the cascade, from lowest to highest precedence: the specification's defaults, the workspace settings' `graphical`, and the manifest's own `graphical`; nothing lies above the manifest. The metrics are the advance widths of the bundled drawing font. The returned `Drawing` contains its box size, its elements in descriptor order, and the code points measured with the font's fallback advance. Layout measures text, places bands and rows, and produces box-local canvas coordinates; it knows nothing about the drawing's position on a page.

The source is flat, one module per step of the specification. `draw` (`box.ts`) takes the member drawings core's `memberDrawings` lists, lays each out, finds the shared start past the name column, and places the bundle's title, the frames with their titles, and the cards with their shadows one under another. A member drawing (`member.ts`) is one timeline taken as the root: `traversal.ts` walks its timelines and fixes its axis, `sides.ts` fills each side outwards in bands, the root band (`root.ts`: the line, its map stack and its wedges) first, then children (`children.ts`), regions (`regions.ts`) and flow control (`flow.ts`) in the placement's order, and above, last, the ancestor band (`ancestors.ts`: the ancestor lines, their chevrons and the member's marks). `segments.ts` draws a segment line's boundaries and labels, `maps.ts` the map stacks, `names.ts` the name column and the centred labels, `fit.ts` the first fit into rows, `heights.ts` a member drawing's heights and `canvas.ts` the distances and canvas positions; `constants.ts`, `numbers.ts`, `metrics.ts`, `defaults.ts`, `cascade.ts` and `elements.ts` hold the constants, the arithmetic, text measurement, the default layer, the cascade and the drawing's types.

The style cascade is represented by `Cascade`, `INITIAL_STYLE`, and `DEFAULT_LAYER`. Each statement selects elements by the members of its `select` object and sets a declaration directly or through a name in the same layer's `styles`. The layer order and the statement rank defined by the specification decide each property independently; inherited properties fall through the element tree, and initial values fill the rest. The cascade runs on each drawing of an element at its own place in that tree, so the two drawings of a timeline drawn as an ancestor line and as a member differ only in the chain of elements holding them, which the selector member `inside` tests. `display: none` removes an element from both the drawing and its layout.

`@timetoalign/tilie-writers` exports `toDescriptors(drawing)`, `writeSvg(placed)` and `writeTikz(placed, options)`. `toDescriptors` returns the ordered SVG-shaped descriptors that an on-screen renderer and both writers share. `placed` is a list of `{drawing, x, y, scale}` values. The writers find the bounding box of all placed drawings, add a margin of 16 on every side, translate each drawing to the page, and apply its uniform scale. Frames, cards and card shadows are written as rounded `rect` elements and an ancestor line's double chevrons as `polyline` elements; the TikZ writer draws the same shapes. `writeSvg` returns one SVG page. `writeTikz` returns a complete LuaLaTeX document by default; `standalone: false` returns the `tikzpicture` environment alone, and `fontDirectory` names the directory containing `DejaVuSans.ttf`. Both writers round the exact value of every double to four decimal places, ties to even, and neither depends on the on-screen renderer.

`pnpm -C app/packages/writers review`, run from the repository root, draws every timeline, group and bundle fixture of the installed schema version except those taken from corpora (`corpus_*`), and the additional resize and style cases, then writes SVG and PNG files plus `index.html` under `app/packages/writers/review/`. The same 46 cases are timeskeleton's 0.7.0 drawing fixtures, which `emit-drawings` writes into a timeskeleton checkout; twelve of their SVG figures are derived by hand from the specification, are never rewritten, and equal the writer's output byte for byte. It rasterizes the SVG files at twice their size with `rsvg-convert --zoom 2`. A temporary fontconfig configuration exposes only timeskeleton's bundled `DejaVuSans.ttf`; the command refuses to render if another font is visible or the rasterizer fails. This review workflow is recorded in [the rasterizer decision](../decisions/0017-rsvg-convert-for-review-renders.md).

The canvas memoizes the drawing per block ([One node per block](#one-node-per-block)). The review command rasterizes writer output for inspection; the application does not expose PNG, JPG, PDF, or `.drawio` export.

## The server

`tilie-server` uses FastAPI and uvicorn. It binds only `127.0.0.1`, generates a random token for each run, rejects foreign Host and Origin headers, and requires `Authorization: Bearer <token>` on every `/api/` route. `tilie` hands the token to the browser in the URL fragment (`http://127.0.0.1:<port>/#token=<token>`). A browser never sends the fragment to the server, so the token does not appear in the access log; the editor reads it, removes it from the address bar and the current history entry with `history.replaceState`, and keeps it in memory only, so reloading the page after the handoff loses the token. Every response carries `Referrer-Policy: no-referrer`, so the browser sends none of the server's URLs to another site. The current server serves the built app from its wheel and implements `/api/health`; `tilie` selects a free port and opens the browser, while `tilie --check` verifies an installation.

The server is intended to load any supported source through `timetoalign` loaders; run conversion-map batches; report unfolding and traversal diagnostics with fix suggestions; validate; export; host a committed OpenAPI document and generated TypeScript client; and proxy a GitHub token. These responsibilities are not exposed by the current API.

## Packages and the dependency ladder

The TypeScript workspace is a one-way ladder enforced by [dependency-cruiser](../app/.dependency-cruiser.cjs). Lower packages never import higher packages. Only the UI packages may import Svelte.

| `@timetoalign/tilie-core` | The workspace view, blocks, ids and order keys; the manifest value of the three file kinds with its load, save, invariants and element addresses; the commands, the store and the workspace file; rationals and coordinates; framework-free. | None |
| `@timetoalign/tilie-layout` | `draw` with its box of frames and cards, member drawings and bands, drawing types, the style cascade, defaults, and font measurement. | core |

| `@timetoalign/tilie-client` | OpenAPI client and Arrow helpers. | core |

Packages for views and embedding are added only when a concrete need appears. `client` has a minimal export, and the ladder keeps `core` free of the browser.

## Testing and quality

Tests are README-first: every `tests/README.md` states the validation logic, and tests follow it. Expected values are exact. Fixtures flow from Python to TypeScript so both sides work from the same examples: `core` loads and saves every 0.7.0 manifest fixture of the schema package byte for byte (29 timeline, 9 group and 9 bundle files), loads every timeline fixture of 0.5.0 and 0.6.0 to what timeskeleton's migration writes, and refuses every shared rejection of every supported version at its pinned path. Property tests with fast-check run generated command sequences from every 0.7.0 timeline, group and bundle fixture, addressing a group or bundle block's elements as its commands do, and check that accepted commands keep the workspace and every block's manifest valid, that refused ones leave the view unchanged, that undo and redo restore every intermediate view, that replaying the journal equals the snapshot, that every journal entry carries its author and the injected clock's time, and that a workspace file reads and writes back to its own bytes. Budgets bound reading and writing a 300-block workspace with a 1,000-entry journal (250 ms each) and dispatching one command (1 ms); the store's decision record holds the figures, 10,000 blocks included. `layout` tests derive exact expected drawings from the drawing specification and cover defaults, the cascade, text metrics, side placement, map stacks and end markers, stretch, requested box size, the box with its frames and cards, segment lines, ancestor lines, and representative fixtures. Writer tests derive descriptors and serialized text from the same specification, check multi-drawing page placement and number formatting, require the twelve hand-derived figures to equal the writer's output byte for byte, parse every review SVG as XML, and compile every review TikZ document under LuaLaTeX with the bundled font. `arranger` tests derive the projection, snapping, the resize values of every mode and handle, the gesture commands, the Delete preview and refusal in every file kind, and the card and boundary under the pointer from the drawing specification by hand; fast-check properties check that a projection of an unchanged view returns the identical node objects, that every gesture yields a command the store accepts, and that undo restores every placement exactly. A component test renders the block node for every drawing fixture of the schema package and compares its element tree with the fixture's SVG.

The canvas itself is tested end to end with Playwright in Chromium, Firefox and WebKit and on an emulated touch screen ([decisions/0021](../decisions/0021-playwright.md)): opening, dragging with snapping and guides, the lock, panning, the selection rectangle, clicks, deletion, order, keyboard moves, undo and redo by keys, resizing in every mode, culling counts at 300 and 900 blocks, and touch drag, pinch and taps; and so is the editor around it: saving, reopening and saving again byte for byte through the fallback file path, a refused file, the About dialog and its notices file, and an inspector edit applied, refused and undone, its form following a drag and a resize live, a resize cancelled with Escape, and a step by key, spin button or wheel applied as one command; a click on the empty canvas whose pointer moves slightly still clears the selection. Group and bundle blocks are tested for what they draw, for selecting an element drawn twice, for Delete in a group block and for hover. Expected values come from the store, read through a test hook, never from pixels. The hook, `window.__tilie` (`load`, `store`, `selection`, `select`, `viewport`, `setViewport`, `locked`, `mode`, `health`, `text`), exists only in development builds and in builds made with `VITE_TILIE_TEST_HOOK=1`. The same builds show a Fixture menu in the editor's header, listing the end-to-end workspaces of `app/e2e/fixtures/` (among them `groups` and `bundles`, which hold the schema package's group and bundle fixtures) and one workspace per group and bundle fixture of the schema package not taken from a corpus, built from the manifest fixture when it is first chosen, with a Load button that opens the chosen one, so a person can try the canvas on prepared workspaces. A production build, and so the wheel, contains neither the hook nor the menu nor the fixture files. The workspaces the suite opens are written by a generator script through the store's commands from the schema package's manifest fixtures, never by hand. axe-core checks the page for accessibility violations ([decisions/0022](../decisions/0022-axe-core.md)). Outside the pinned Playwright container image, `e2e/run.ts` runs the suite inside it through rootless podman, with `app/` mounted at its own path; a schema package linked from a sibling checkout lies outside `app/`, so it is mounted too, read-only at its own absolute path, where the links in `node_modules` find it (`e2e/container.ts`). Screenshots of the block nodes, the `groups` workspace among them, are compared with zero tolerance, only inside that image, where their baselines are made. Current gates include Biome, Vitest, fast-check, dependency-cruiser, svelte-check, Playwright, axe-core, LuaLaTeX, Ruff, and pytest.

The editor shell test covers the token handoff through the fragment and the absent token; it does not currently cover its CSS grid layout, mobile rendering, or a fragment carrying an empty token. The server static-file tests do not currently cover traversal behavior. These limits are documented coverage gaps rather than claims of behavior.

## Performance

A drag costs script time on every pointer move in proportion to the total number of nodes, culled or not, because Svelte Flow re-adopts its whole node list on each move. Measured in headless Chromium: about 1.2 ms per move at 100 blocks, 2.4 ms at 300 and 5 ms at 900. Culling reduces what is mounted (42 of 300 nodes in a zoomed view) but adds its own cost to pan and zoom (3.1 ms per wheel event at 300 blocks with culling against 0.4 ms without), so it starts above 500 blocks. One node per block, a complete projection, reused node objects and memoized drawings keep a gesture from doing any work of TiLiE's own until it ends.

The budgets, for a workspace of 300 blocks in Chromium, are checked by `pnpm e2e:budget` from the DevTools Protocol's script time: dragging a block at most 3 ms of script per pointer move; panning and wheel zoom at most 1 ms per move or event; one command at most 1 ms; one block's re-drawing within one frame (16.7 ms). Heavy data is intended to stay out of the DOM, in WebGL panes and columnar tables, with parsing that could block interaction in workers; server calls do not occur for every keystroke.

## Automation

The command layer (`parseCommand` and `apply` over a workspace view) and the server's OpenAPI document are the intended contracts for programmatic use. An MCP server and a command channel for live sessions are reserved for a future addition. At present, the only API route is the protected health endpoint.

Each dependency requires an ADR under [`decisions/`](../decisions/). The records use MADR headings, weigh writing the component ourselves, record maintenance and exit costs, name audited versions, and include review dates. See [the ADR convention](../decisions/0001-record-architecture-decisions.md), [the TypeScript choice](../decisions/0002-typescript.md), [the Svelte and Vite choice](../decisions/0003-svelte-5-with-vite.md), [the pnpm workspace choice](../decisions/0004-pnpm-workspaces.md), [the Biome choice](../decisions/0005-biome.md), [the Vitest choice](../decisions/0006-vitest.md), [the dependency-cruiser choice](../decisions/0007-dependency-cruiser.md), [the FastAPI and uvicorn choice](../decisions/0008-fastapi-and-uvicorn.md), [the Python tooling choice](../decisions/0009-uv-hatchling-ruff.md), [the wheel bundling decision](../decisions/0010-wheel-bundles-the-built-app.md), [the exact rationals written in core](../decisions/0011-exact-rationals-written-in-core.md), [the schema package](../decisions/0012-timeskeleton-package.md), [the fast-check choice](../decisions/0014-fast-check.md), [TeX Live for the TikZ checks](../decisions/0015-tex-live-for-tikz-checks.md), [the fractional indices written in core](../decisions/0016-fractional-indexing.md), [rsvg-convert for review renders](../decisions/0017-rsvg-convert-for-review-renders.md), [the autosave written in `editor`](../decisions/0018-indexeddb-autosave.md), [the workspace store and its journal](../decisions/0019-workspace-store-and-journal.md), [Svelte Flow for the canvas](../decisions/0020-svelte-flow.md), [Playwright for the end-to-end tests](../decisions/0021-playwright.md), [axe-core for accessibility checks](../decisions/0022-axe-core.md), [the file access written in `editor`](../decisions/0023-file-access-written-in-editor.md), [the YAML library](../decisions/0024-yaml-library.md), and [the TOML library](../decisions/0025-toml-library.md).

Package manifests (`package.json`, `pyproject.toml`) declare compatible ranges for runtime and peer dependencies, such as `fastapi>=0.141,<1` in the server and `svelte` `^5.57.1` in `editor`; development dependencies, the npm `devDependencies` and the server's `dev` group, are pinned exactly. Lockfiles pin every resolved version: `server/uv.lock` for Python and `app/pnpm-lock.yaml` for the application. A version must have been released at least 14 days before it enters a lockfile, and the ADR identifies the audited version. The one exception to that window is this project's own schema package, `@timetoalign/timeskeleton` (`minimumReleaseAgeExclude` in `app/pnpm-workspace.yaml`), so that a schema release can be consumed as soon as it is published. The same package is also the one exception to compatible ranges: while TiLiE is built against a schema version that is not yet released, as it is now against schema 0.7.0, the packages that use it (`core`, `layout`, `writers`, `arranger` and `editor`) depend on it through a committed `link:` to the built `js/` directory of a timeskeleton checkout beside this repository (`../timeskeleton/js`), and the repository is not published in that state; once the version is released, the `link:` is replaced by a compatible range from npm (`^0.7.0`). This policy deliberately separates compatibility declarations from reproducible resolutions.

## Deployment

Install the current product with `pip install tilie-server`, then run `tilie`. The installed wheel contains the built browser app, so starting it does not require Node.js or a runtime download.

The deployment model is intended to grow toward a hosted browser app that communicates with a user-run local server, a desktop wrapper, and collaborative hosting. Those deployment forms are not available today.
