# Architecture

## Overview

TimeLineEditor (TiLiE) is a browser editor and visualization tool for musical timelines represented by `timetoalign`. It works with three layers, each named by one word only:

- a **manifest** is one TimeSkeleton manifest as the `timeskeleton` schema (version 0.7.0) describes it. Every manifest has one shape, `{timeskeleton, timelines, id?, name?, meta?, groups?, graphical?}`, whatever it holds: one root timeline, several, a group, or several groups beside ungrouped timelines; every manifest is an alignment bundle, also when it holds one timeline or one group. A timeline has exact coordinates, children at exact offsets, conversion maps, regions, flow control, measure maps and metric hierarchies, and a `length` that may be `null`, not known; `graphical` holds the style rules of the manifest's own drawing and its groups' display orders. Every timeline, group, conversion map, region, break, jump and marker has an `id`, and so may the manifest; a `name` is what is displayed. Timeline ids, group ids and the manifest's id are unique together across the manifest, and every other id within its root's tree. A manifest with an `id` or a `name` is a named bundle, one with neither an anonymous bundle. A manifest knows nothing about where, or how often, it is shown;
- a **block** carries one manifest, entirely its own, together with its placement, the other inputs of its drawing: position, scale, graphical length, vertical spacing, requested box size, band order, the band orders of its groups and timelines, and the places of its drawing's items with the sizes and vertical stretches of its members' cards. A block's styling is its manifest's `graphical`; the block has no style layer of its own;
- a **workspace** is the canvas: its blocks, their order, the workspace settings, and the command journal that produced them, with the sessions of its editors. Block ids are the workspace's namespace, and an address names anything in it.

TiLiE is local-first from the start: the browser communicates with a local Python server. The server is not an incidental wrapper. It owns loading through `timetoalign`, heavy computation, and exports, while the browser keeps a small editing core. This division keeps Python library capabilities close to the operations that need them and keeps interaction responsive without a per-keystroke network request.

## What exists today and what is planned

`tilie-server` starts a FastAPI server on loopback, serves the built editor, and answers authenticated `GET /api/health`. The editor is a header and the canvas, which fills the rest of the page, with an inspector drawer on the right. It opens, saves, imports and exports files, autosaves in the browser, and inspects and edits the selected block's manifest ([The editor](#the-editor)); a block, a group or a timeline opens in an editor of its own on the canvas ([Editors](#editors)); everything it changes goes through the commands of `core`.

Of the six workspace packages, `core` implements the three layers: exact numbers, validated manifest load (any manifest of schema 0.7.0, read in its complete form) and save (the complete form, or the minimal one on request), Delete with everything it takes along, the immutable workspace view with its blocks, ids and order, the four commands over addresses, a store with its command journal and its editor sessions, the rule that an editor has no side effects, and the workspace file ([The core package](#the-core-package)). `layout` derives a drawing from a manifest, placement, style layers, and font metrics; `writers` turns a drawing into element descriptors and writes placed drawings as SVG or TikZ ([Layout and writers](#layout-and-writers)). `arranger` shows a workspace on a canvas and turns every completed gesture into one command ([The canvas](#the-canvas)). `editor` mounts the canvas on one store, opens and saves files, inspects manifests, and autosaves a workspace's text in IndexedDB ([The editor](#the-editor), [Autosave](#autosave)). `client` only establishes its export, strict type checks, dependency boundaries, and tests.

Loading sources through the server, raster exports, generated API clients, collaboration over a network, and automation endpoints are not implemented. Except for the packages, the canvas and the editor described as built, the remaining sections describe the intended architecture so additions have explicit boundaries; they do not describe current behavior as available functionality.

## The canvas

The canvas is a data-driven renderer hosted by a diagram engine. It has two levels. At the workspace level, blocks are placed freely: drag, snap, selection, pan, zoom, resize and z-order. A block draws one manifest, whatever it holds. Inside a block, its groups and timelines are arranged in editors, modes of the same canvas ([Editors](#editors)).

At the block level, the drawing comes from the manifest rather than from an editable drawing surface. Every manifest is drawn the same way: a grey box that opens with the manifest's title, its `name`, or its `id` when it has no name (an anonymous bundle has no title); each group a **frame**, a rounded rectangle holding the group's title and its members' cards one under the other in display order; and each timeline drawn as a root (a group's member or an ungrouped root) in its own **card**, a raised rounded rectangle with a shadow offset to the right and down. The box's **items**, its frames and its ungrouped roots' cards, each lie at their own **place**, `{x, y, length, scale, spacing, width, height}`, any member of which the block may state (the rest default, so that items lie one under the other); a group's member cards always lie one under the other in display order, and each may state only its own `width`, `height` and `spacing`, the length and scale it is drawn with being its group's. A timeline drawn as a root is stretched vertically by the block's `spacing` times its item's, and a member's also times its card's. The box has one horizontal layout: every item starts its lines after one name column and ends them with one right margin, so items of one length are equally wide wherever they lie, and the members of a group share their frame's graphical length and scale, so they begin and end at the same x. An item's scale scales everything in it about its top left corner. The manifest's title lies at the box's top left corner, above every item: an item placed higher grows the box upward and pushes the title with it. Within its card, `draw` maps time to x through the item's graphical length, applies the vertical spacing and requested sizes, lays out children, regions and flow control in bands and rows in the root's band order (its own, else its group's, else the block's), and stacks each timeline's conversion maps against its own line. A segment line draws its segments on its own line, separated by boundaries. A top-level timeline ends with an arrowhead (an open one for a segment line), or with a filled circle when it is locked; a child ends with an open diamond, locked or not. A timeline of unknown length is scaled to its **reach**, the farthest coordinate its content reaches, and its line runs on past it into three chevrons, whatever the timeline is (an ancestor line that runs on has two, so the marks are told apart): a root of unknown length has no end wedge and no end label, and one without content is still drawn at the full graphical length. A member that is a child timeline also draws its ancestors above its line as **ancestor lines**, clipped to the member: where an ancestor reaches beyond the member's start or end, its line runs on into a double chevron, and two marks label the member's start and end on the ancestor's axis. So one timeline may be drawn more than once, as an ancestor line of several members or also as a member. A placed drawing has a canvas position and a uniform scale. A person edits the underlying manifest through commands, never by dragging an arrow endpoint. This preserves the meaning of a musical relation independently of a particular display.

`@timetoalign/tilie-arranger` builds the workspace level on [Svelte Flow](https://svelteflow.dev) (`@xyflow/svelte`), which supplies pan and zoom, node dragging, the selection rectangle, keyboard focus and culling ([decisions/0020](../decisions/0020-svelte-flow.md)). No other package imports it. The arranger's plain TypeScript (`project`, `snap`, `resize`, the gesture commands, and the editors' `editors`, `items`, `reorder`, `focus` and `marquee`) holds every rule below and is tested without a browser; its Svelte components (`Canvas`, `BlockNode`, `CanvasToolbar`, `ResizeToolbar`, `GapMenu`, `SnapGuides`), the drag attachments of `gestures.svelte.ts` and the `slide` animation of `motion.ts` connect those functions to Svelte Flow.

### One node per block

`project(view, selection, previous, metrics, editing, preview?)` returns one Svelte Flow node per block, in index order, `editing` being the innermost open editor or `null`. A node's id is the block id. A block's `x` and `y` are the canvas position of its drawing's place origin, so the node's `position` is that point less the drawing's origin `(Ox, Oy)` times the scale (`nodePosition`): a box that grows left or up moves nothing else on the canvas, and every gesture that reads or writes a block's position converts between the two. Its `width` and `height` are the drawing's box times the block's scale, given again as `measured`, with `handles: []`, so the node is complete and Svelte Flow never measures it. A node that Svelte Flow has to measure is mounted even when it lies outside the view, which would defeat culling. `selected` says whether the block id is in the selection, `zIndex` is the block's rank among its siblings by `index`, and `data` carries the block, its drawing, the drawing's descriptors, the ids of its selected elements and whether it holds any, the open editor and the addresses of its drawing that lie inside the edited element (every address without an editor and in the bundle editor, none in another block). With an editor open, every other node is neither selectable nor draggable and carries the class `tilie-outside`, and the edited block's node is not draggable. A node of `previous` whose block, drawing, position, rank, selection and editor are unchanged is returned as the same object, and Svelte Flow skips an object it has already adopted; a change to one block re-renders one node.

`drawingOf(block, settings, metrics)` draws a block at its placement, its band orders and places included, with the layers `DEFAULT_LAYER`, the workspace's `graphical` and the manifest's own `graphical`. Blocks are immutable, so the drawing is memoized per block object and recomputed only when the settings or the metrics change identity; the descriptors are memoized per drawing. Neither is stored in the workspace or the file.

`BlockNode` renders the descriptors as Svelte elements inside one `<svg>` per node, whose `viewBox` is the drawing's box and whose size is that box times the scale. Every attribute is the text the SVG writer writes, so the node's element tree equals the exported SVG's, element for element. Text is rendered as text, never parsed as markup: names and labels are user data. Every drawn element carries its address in `data-address`, every drawing of an element drawn more than once included. A drawing has three kinds of box: the block's own box, a group's frame and a timeline's card. While the pointer is over a block, the innermost card or frame under it is marked with `data-hovered`, a soft glow that shows which box the pointer is in (the block's own box is never marked, since the node shows its block); a segment boundary under the pointer is marked too, drawn in the accent colour. One module, `boxes.ts`, maps a pointer target to what it hits, a box or another drawn element, classified by the drawing's element types rather than by the form of its address, and decides both what a press selects and what is hover-marked, only inside the edited element while an editor is open; which editor a double-click opens is decided in `editors.ts` from the same hit. The marks act on nothing and are never stored. The drawings use the DejaVu Sans file bundled by timeskeleton, declared under a family name of its own so that a system copy never stands in for it, and they are mounted only once that face has loaded.

### Preview during a gesture, one command at its end

The canvas reads the store through `liveStore(store)`, the arranger's one reactive adapter of the store, which the editor makes once per store and passes to the canvas, the inspector and the inspector's editing bar: each of its getters (`view`, `editing`, `entries`, `listed`, `journal`, `sessions`, `changes`) reads the store itself and is read again after every change the store's `subscribe` reports, so no component keeps a copy. The canvas's nodes are a writable `$derived` of the view, the selection and the resize preview, bound to Svelte Flow with `bind:nodes`. During a drag Svelte Flow writes the dragged positions into that value, and nothing else runs. On release the arranger builds one command, the store applies it, and the view's change derives the nodes again, replacing the preview with the stored positions. A gesture that stores nothing restores the projection. Undo and redo are exact, because the canvas shows nothing between two commands that the next command does not either store or discard.

- A drag of n blocks is one `set` with n changes `{x, y}`.
- A keyboard move (an arrow key moves the selected blocks one grid step, Shift and an arrow key eight) is one `set`.
- A resize of a block is one `set` on its block.
- A change of order is one `set` of `index` (see below).
- Delete is one `remove`.
- On the arranger and in the bundle editor, a resize of a frame or card is one `set`: the places it changes, and the drawn position of every other item that states none, the frame holding a resized member's card excepted; a move of an item in the bundle editor likewise.
- In the group and timeline editors, a resize of a frame or card is one `set` of the places it changes.
- In the group editor, a drop of a member card is one `set` of the group's `order`.

Opening an editor, Done and Cancel are store operations, as undo and redo are, never commands.

### Numbers on the canvas

Canvas numbers are doubles, and the positions Svelte Flow reports carry binary noise. Before a number is stored it is quantized: a position to the grid when the workspace snaps to its grid, every other number (and every position when the grid does not snap) to 1/2048 unit. 2048 is the bundled font's units per em, so at an integral font size and scale every text-derived edge and plot origin is a multiple of 1/2048, and a position aligned to one is stored exactly.

While a block is dragged, Svelte Flow snaps it to the grid (`snapGrid`). The arranger then aligns the dragged block horizontally: its left edge or its plot origin (the canvas x of the start of its root's line) moves onto the nearest left edge or plot origin of another block lying within 6 screen pixels, and a vertical guide line is drawn there for as long as the alignment holds. The other dragged blocks move by the same offset. Svelte Flow has no alignment guides of its own.

### Resizing

Every box is resized the same way: a block, a group's frame, an ungrouped root's card and a group member's card each offer three modes, Scale, Box and Stretch, wherever the level holding it resizes it ([Editors](#editors)). A block's modes each change a different input of its drawing:

- **Scale** sets `scale`: everything grows or shrinks with its proportions, text included. Only the four corner handles are offered; the new scale is the larger of the two axis ratios, never below 1/8.
- **Box** sets `width` and `height`: the box changes and the content keeps its place at the top left. A request at or below the content's own extent stores `null`, so the box follows the content when it later grows.
- **Stretch** sets `length` from the left and right handles, `spacing` from the top and bottom ones and both from a corner: lengths and distances stretch, while markers, line widths and text keep their size. The content's width grows with `length` and its height with `spacing` in piecewise-linear steps, as timeskeleton's drawing specification derives them, so the values that put the dragged edge under the pointer are solved for numerically. The floors are 8 for `length` and 1/4 for `spacing`. A box enlarged beyond its content keeps its proportion to the content while the content stretches, so every margin stretches with it and the dragged edge still ends under the pointer: `width` and `height` become the request times the stretched content's size divided by the content's size before (multiplied first), and a request no larger than the content becomes `null`. The values are solved on the box's extent, the larger of the content and the request following it, so a pointer moved back always finds a smaller length or spacing.

In every mode the dragged edge ends under the pointer, the opposite edge stays put, and a left or top handle also stores the block's new `x` or `y`. A stretch scales every place the block states with it, `x`, `length` and `width` by the ratio of the lengths and `y` and `height` by that of the spacings, every `scale` and `spacing` kept, since an item's `spacing` is a factor of the block's (`blockStretchPlaces`), so the items keep their arrangement. While the pointer is down, the block is drawn at the previewed values, so the preview is exactly what the command will store.

A frame or card resizes in the same three modes by changing the block's `places` (timeskeleton's drawing specification, section 8.6): Scale and Box change one entry, a Stretch also the stated sizes of the boxes whose content it stretches. A group's frame or an ungrouped root's card: Scale sets its `scale` from a corner handle, the opposite corner staying put (scale 1 is left unstated); Box sets its `width` and `height` from any of the eight handles, a request at or below its content's own size unstating it; Stretch sets its `length` from its left and right edges, its `spacing` from its top and bottom ones and both from a corner, and every stated `width` or `height` of the frame or card and of its members' cards follows its content in proportion, as a block's does, so the members' lines keep one length and every margin stretches with them. A group member's card: Scale sets its group's `scale`; a horizontal Stretch sets its group's `length`, since the members of a group share it, the stated widths of the frame and of every member's card following in proportion; a vertical Stretch sets the card's own `spacing`, the stated heights of the card and of its frame following; Box sets the card's own `width` and `height`. As its frame decides where the card lies, a member's card scales from its bottom right corner and sizes or stretches its box from its right and bottom edges and that corner. The dragged box, the frame or card, or the member's card, ends under the pointer. Sizes are in the item's own coordinates, before its scale, and every value is quantized to 1/2048 unit. The frame and the box adapt to every such resize, except that in the group editor the frame keeps its width: a horizontal Stretch of the members, on the frame or on a member's card, runs from the right only, states the frame's `width` at its drawn width and stops where the cards would pass it, the frame's content following the pointer; the frame's Stretch there offers every handle but the left edge and the left corners, and vertically the frame adapts.

When exactly one box that the level resizes is selected, a block or, on the arranger and inside an editor, a frame or card, a toolbar centred above that box, 10 px clear of its top at any zoom, offers the modes as three buttons, Scale, Box and Stretch; the keys 1, 2 and 3 choose them too. It is placed by the rule of Svelte Flow's `NodeToolbar` (`getNodeToolbarTransform`) applied to the box rather than to a node, so it follows the box through a move, a resize and every pan or zoom. The pressed button shows its mode's handles, on a block four corners for Scale and eight handles for Box and Stretch, on a frame or card those named above. The mode is the viewer's own and stays when the selection changes. The handles are the arranger's own elements rather than Svelte Flow's resize controls, because a box's size during a resize is whatever its drawing measures at the previewed placement; the pointer only provides a distance in canvas units.

### Selection, marquee and deletion

The selection is a set of addresses: block ids and `<block>/<element address>` ([Ids, addresses and order](#ids-addresses-and-order)). It alone decides which blocks the canvas shows as selected; Svelte Flow's own selection flags are reset to it after every click and selection rectangle. A selected address is marked at every place it is drawn, so selecting a timeline drawn both as an ancestor line and as a member marks both lines. Every box, whether a timeline's card, a group's frame or the block, shows a blue line, the contains-selection mark, whenever the selection holds an element drawn inside it other than the box itself: a card holds its timeline's drawing, a frame its members' cards and everything they hold, and the block everything it draws. So selecting a timeline's line marks its card, the frame of its group and the block at once. The mark is bold on the card and thins outward: 3 px dashed on a card, 2 px dashed on a frame and 1 px dotted on the block, measured on screen at every zoom. A selected box keeps its glow.

- A click on a drawn element selects that element only, found by the nearest `data-address` around the click.
- A press on a box selects that box: a click on a timeline's card, or on its shadow, selects the card (`<block>/<timeline>/card`); one on a group's frame, outside its cards, selects the group; one on the block's own area, outside its frames and cards, selects the block. A selected card glows on its own rectangle, not on its shadow, and a selected frame glows as a selected card does; either keeps that glow under the pointer and whatever else the selection holds. Delete on a selected card removes its timeline, so everything the card holds is marked as affected, and the inspector shows its timeline's `locked`.
- Shift and a click add the address to the selection, or remove it when it is selected.
- A click on the empty canvas clears the selection, blocks and elements, in either mode; Shift and a click there leave it as it is. A press whose pointer moves at most 4 px before it is released is still a click (Svelte Flow's `paneClickDistance`), so a tap or a trackpad click that moves slightly never becomes an empty selection rectangle.
- Escape cancels a gesture in progress, a resize restoring the stored values; when none is running it clears the selection, and with nothing selected it closes the innermost editor ([Editors](#editors)).
- A focused block is selected with Enter or Space.
- A drag that starts anywhere on a block, on one of its elements included, moves the block. A drag on a block that is not selected, and holds no selected element, first selects that block alone.

A plain drag on the empty canvas pans. Shift and a drag draw a selection rectangle instead, which replaces the selection with exactly the blocks lying wholly inside it (in an editor, the elements; [Editors](#editors)).

The Marquee button of the canvas controls (accessible name "Add to selection (marquee)") switches to an additive mode, which is also how a touch screen selects several items. While it is pressed, a drag on the empty canvas draws a selection rectangle instead of panning, and the blocks wholly inside it are added to the selection. Every click, Enter or Space adds its address, or removes it when it is already selected, as Shift does outside the mode. A click on the empty canvas still clears the selection; the end of a selection rectangle is no click.

Delete or Backspace removes exactly the selected addresses as one `remove`, blocks and elements mixed, timelines (root or child) and groups included, in every manifest; a segment is the exception, described below. A selected part of an element, such as its name or its label, stands for the element. While elements are selected, the elements a Delete would take with them (the descendants of a selected timeline and everything they hold, and the conversion maps that name a removed timeline) are marked with `data-affected`. What goes with a removed timeline, and what stays, is `core`'s ([Commands](#commands)): a group left without members stays, and deleting a group keeps its members as timelines of the manifest. Removing the last root leaves an empty box; the box goes only with its block. A selection that holds a manifest's title is refused whole, because a title goes only with its block; the canvas shows why in a status region that screen readers announce, with the advice to select the block.

Deleting a segment, a child of a segment line, would leave a gap in the line, and is not supported yet. Delete on a selection holding a segment that leaves a gap, or a part of one such as its label, is refused whole, and the status region shows "Deleting a segment is not supported yet."; the refusal comes before any way of closing the gap is looked up, so the refusal is the same whichever ways would be permitted. A segment removed with its own segment line, an ancestor or its block leaves no gap and goes with it.

The menu that will close the gap is kept: `arranger` exports it and its tests prove it, but the canvas does not mount it. It is a small form named "Delete segment <id>", styled like the resize options (the shared `.tilie-menu` styles), holding one fieldset, "Closes the gap", of four radio buttons, each named after the neighbour that moves and described by one line, then OK and Cancel, which Enter and Escape also give. For a segment S of length l in the segment line Λ, the four ways are `core`'s:

- **Left extends**: the segment before S grows by l.
- **Right extends**: the segment after S starts where S started and grows by l.
- **Left shifts**: Λ's offset in its parent grows by l and Λ shortens by l, so the earlier segments move on by l and the later ones keep their place in the parent.
- **Right shifts**: every later segment moves back by l, and Λ shortens by l.

`core`'s `segmentGaps` decides which ways are permitted: extending needs a neighbour on that side whose length may change (one not locked, as a segment is not unless it is a segment line itself, or of unknown length); shifting needs Λ not locked, and shifting left needs Λ to be a child; and the manifest the way leaves must pass the schema and the invariants, so that a segment line that is itself a segment cannot change its length. A length that is not known stays unknown, and a neighbour growing by an unknown length becomes of unknown length. A way that is not permitted is disabled, its title naming why, and the first permitted way, in the order listed above, is chosen when the menu opens; OK gives the chosen way, which the canvas will dispatch as one `remove` carrying it as `gap`. A top-level segment line that a shift shortens is still drawn at the full graphical length, as every drawn root is, so its remaining segments widen to fill the gap from both sides; that is the intended drawing once deleting a segment is enabled.

### Editors

An **editor** is a mode of the arranger on one element, on the same canvas, never a pane or a second canvas. There are three kinds, chosen by the box that is hit and never by what it holds (`editorTargetOf`): the block's own box opens the **bundle editor**, a group's frame the **group editor**, and a timeline's card or line, a root's or a child's, the **timeline editor**. A double-click, a double tap (two taps within 300 ms and 10 px of each other where a double-click would do the same) or Enter on a single selected box or timeline opens its editor; Svelte Flow's double-click zoom is off. A double-click or a double tap on any other element inside a card or frame, such as a name, a label, a region or a group's title, opens the innermost card or frame under the pointer, while a child's line opens the child's editor; an element in no card or frame, such as the manifest's title, opens nothing, and Enter on a selected element that is no box and no timeline opens nothing either. Inside an editor, every box or timeline inside the edited element, at any depth, opens its own editor on top of it; a double-click or a double tap on the edited element itself does nothing, and one outside it (on the pane, on another block or on the faded rest of its block) closes the innermost editor, exactly as Done does. Outside every editor a double-click on the pane does nothing. The open editors, outermost first, form the **editing path**. It is the store's (`store.editing`, [The store and its journal](#the-store-and-its-journal)), one source for the canvas, the inspector and the test hook.

Opening an editor animates the view in about one second (`FOCUS_DURATION`, 1000 ms; at once when the viewer prefers reduced motion) so that the edited element is centred in the canvas left of the inspector drawer, with a margin of 10 % on each side and the zoom kept between 0.05 and 4 (`focusViewport`); closing it animates back to where that level's view was. While an editor is open, a change of the canvas's size (the inspector drawer opening or closing, the window resized) centres the edited element again for the new size, the same way; the view that closing the editor returns to stays the one it was entered from. Everything outside the edited element, other blocks and the rest of its own block alike, is faded to an opacity of 0.3 and inert: nothing there is hovered, selected or moved, and a drag there pans. A click on the empty pane clears the selection, as on the arranger, while a click on a faded block, which lets the pointer through to the pane, changes nothing. Opening an editor keeps only the selected addresses that lie inside the edited element, and in the bundle editor the block itself; the edited group or timeline itself and its card are dropped too, since a gesture on them would be refused. Inside, every element is selectable by click, and a marquee selects the elements lying wholly inside it (`elementsInRect`), so that the properties of several elements can be changed at once; boxes are selected by click.

What each level offers is two tables in code, so that a later editor adds a row or a level rather than a branch: `GESTURES`, one row per level, for moving, reordering and the marquee, and `RESIZING`, one row per kind of box, naming the levels where it resizes and what each mode writes:

| Level | Move | Resize | Reorder | Marquee selects |
| --- | --- | --- | --- | --- |
| Arranger | blocks | every block, frame and card: Scale, Box, Stretch | none | blocks |
| Bundle editor | groups' frames and ungrouped cards, freely inside the box | the edited block itself and every frame and card in it: Scale, Box, Stretch | none | elements |
| Group editor | none | the edited frame itself and its members' cards: Scale, Box, Stretch; a horizontal Stretch of the members, on the frame or a card, runs from the right, every member at once and live, never past the frame, which keeps its width; a vertical one stretches the frame or the card, the frame adapting | the member cards, by drag and drop | elements |
| Timeline editor | none | the edited card itself, an ungrouped root's or a member's: Scale, Box, Stretch (a member's card scales its whole group and stretches it along time, its siblings' lines and margins included; vertically it stretches only its own card, its frame's stated height following); nothing for a child, which has no box | none | elements |

A move in the bundle editor, and a resize of a frame or card on the arranger or in the bundle editor, states, in the same `set`, the drawn `x` and `y` of every other item that states none, the frame holding a resized member's card excepted, so that no other item moves (`itemMoveCommand`, `itemResizeCommand`, and the Properties form through the same `placeCommand` and `keepsItems`); in the group and timeline editors a resize states only the places it changes, and an item below may follow it down, its container adapting. A member card dragged in the group editor previews the order a drop would give, the dragged card before the first card whose middle lies below the pointer (`memberOrderAt`), by drawing the block in that order, the dragged card following the pointer while the other cards slide apart (`slide`, a function for Svelte's `animate:` directive). The cards slide only while a member drag previews an order and through the redraw of its drop or abort, never on another redraw (a resize preview, an item drag, an edit, an undo), and they move at once when the viewer prefers reduced motion; the drop is one `set` of the group's `order`, or nothing when the order is unchanged (`reorderCommand`). Drags inside a drawing run on pointer attachments (`itemDrag`, `memberDrag`) that mark their element `nodrag nopan` for Svelte Flow: a press that moves at most 4 px is still a click and selects, the press that starts a drag selects the dragged item, the click that ends a drag selects nothing more, and Escape aborts the drag, which stores nothing. A child's timeline editor opens, fades its surroundings and closes, with nothing to arrange yet.

An editor has no side effects: a command made in it changes only the edited element and what it holds, and the containers adapting, a block's box growing or moving, is no side effect; so is a frame resized in the group editor, which sets only the places of the group and of its members' cards, so that the later items with a default position may move, and a member's card scaled or stretched in its timeline editor, which sets its group's `scale`, or its `length` with the stated widths of the frame and of the members' cards kept in proportion, all shared by the members, or its own card's `spacing` with the stated heights of the card and of its frame. `core` enforces the rule ([No side effects](#no-side-effects)); a refused command leaves everything as it was, and the status region names what lay outside.

Done closes the innermost editor and keeps its changes, as one entry of the level below; Escape does the same once no gesture runs and nothing is selected, and so does a double-click or a double tap outside the edited element. Cancel closes it and restores everything as it was when it opened. Both are the inspector's ([The inspector](#the-inspector)).

### Order

The order of blocks is their `index`, a fractional index among siblings, and it is projected as the nodes' `zIndex`; selecting a block does not raise it. Ctrl and `]` (Cmd on macOS) move the selected blocks one place forward past the next unselected block, Ctrl and `[` one place backward, and with Shift to the front or the back. Only the moved blocks receive new indices, each between its new neighbours.

### Keys

The canvas reads its keys before Svelte Flow does, so that a key is handled once; keys typed into a text field are left alone. The canvas is one tab stop (an ARIA `application` named "Arranger"); it takes the focus when the editor opens, when a workspace is opened, and when it is pressed. Its keys apply only while the focus lies on the canvas or inside it, so a key pressed with the focus on the page's body, the header or the inspector does nothing on the canvas. Undo, redo and the file shortcuts are the page's, not the canvas's ([The editor](#the-editor)); they are listed here because they work on the canvas too.

| Key | Action |
| --- | --- |
| Tab, Enter or Space | Focus a block, select the focused block |
| Enter, with one box or timeline selected | Open its editor |
| Double-click, double tap | Open the editor of the timeline line or the innermost box under the pointer; outside the edited element, close the innermost editor (Done) |
| Wheel, Shift and the wheel | Pan vertically, pan horizontally |
| Ctrl and the wheel (Cmd on macOS), a pinch | Zoom |
| Arrow keys, Shift and an arrow key | Move the selected blocks one grid step, eight grid steps (on the arranger) |
| Delete, Backspace | Remove the selected addresses; refused on a segment, whose deletion is not supported yet |
| `+`, `-`, `0` | Zoom in, zoom out, fit every block into view |
| Ctrl+Z; Ctrl+Shift+Z or Ctrl+Y (Cmd+Z, Cmd+Shift+Z on macOS) | Undo, redo |
| Ctrl+`]`, Ctrl+`[`, with Shift | Forward, backward; front, back |
| 1, 2, 3 | Resize mode Scale, Box, Stretch |
| L | Lock or unlock the canvas |
| Escape | Cancel a gesture in progress; otherwise clear the selection; otherwise close the innermost editor |

Svelte Flow pans on the wheel (`panOnScroll`) and zooms only with Ctrl or Cmd held (`zoomActivationKey`); a touchpad pinch, which browsers report as a wheel event with Ctrl, zooms too, and so does a two-finger pinch on a touch screen. Outside macOS, Chromium and Firefox already report a Shift wheel as horizontal travel, which Svelte Flow would discard while converting vertical travel; the canvas pans such an event horizontally itself, at Svelte Flow's speed (half a pixel per pixel of travel, a line counted as 20 pixels).

### The lock

The Lock button of the canvas controls, or L, locks the canvas. A locked canvas changes no placement: a drag on a block pans the canvas instead of moving the block, the arrow keys move nothing, the resize handles are hidden and the mode buttons are disabled. Selecting, deleting, reordering, panning and zooming stay available.

### Overlays and culling

The resize handles and the alignment guides lie in one overlay layer, Svelte Flow's viewport portal in front of the nodes, stacked above any block; they scale inversely with the zoom so that they keep their screen size. The canvas controls (zoom in, zoom out, fit, Lock, Marquee) are a vertical stack of icon buttons at the bottom left of the canvas, Svelte Flow's controls panel holding the editor's own buttons; each has an accessible name and a tooltip naming its key, and the stack is one toolbar whose buttons the Up and Down arrow keys move between.

Above 500 blocks only the blocks in view are mounted (Svelte Flow's `onlyRenderVisibleElements`); a block partly in view is mounted whole. Below that count culling costs more than it saves, as the measurements in [Performance](#performance) show.

### Per-viewer state

The selection, the viewport, the lock and the resize mode belong to the person viewing the canvas: the editor holds them, and they are never stored in the workspace or its file, so a text diff of two workspace files shows only real changes. The open editors are the store's, not the viewer's: a file saved while an editor is open holds its session folded, as Done would fold it, and a reopened file opens no editor. A newly opened workspace is fitted into view. Svelte Flow's attribution link is hidden (`proOptions.hideAttribution`, which its MIT licence permits); the editor's About dialog credits it instead.

## The editor

`@timetoalign/tilie-editor` is the application around the canvas. Every change it makes to a workspace is a command dispatched to the store, so undo, redo, the journal and the autosave cover it as they cover a gesture.

### The header and the File menu

The header holds the title, the File menu, the open file's name, a quiet "offline" mark while the server's health check fails (its reason in the mark's tooltip and in text for screen readers), and the About button. The file name, and the page's title, start with `•` while the workspace has changes it was not opened or saved with; undoing back to the saved state removes the mark.

The File menu is a WAI-ARIA menu button: Enter, Space or the down arrow open it on its first item, the up arrow on its last; the arrows, Home and End move between the items, and Escape closes it.

| Item | Shortcut | Action |
| --- | --- | --- |
| New workspace | | An empty workspace named `untitled.tle.json` |
| Open… | Ctrl+O (Cmd+O) | A `.tle.json` file, read with `readWorkspace` into a new store |
| Save | Ctrl+S (Cmd+S) | The workspace written with `writeWorkspace`, back into the file it was opened from or last saved to |

Where the browser has the File System Access API, the editor opens and saves through its pickers and keeps the file's handle, so Save writes back without asking again. Elsewhere it opens through a file input and saves by downloading the file under its name ([decisions/0023](../decisions/0023-file-access-written-in-editor.md)). A cancelled picker does nothing. New workspace and Open… on a workspace with unsaved changes first ask whether to discard them, with Cancel focused. A file that cannot be read leaves the open workspace as it is and shows a dismissible message listing the reader's problems, each with the JSON pointer of its place in the file; editing goes on while messages are shown.

The file shortcuts and undo and redo work wherever the focus is outside a dialog; undo and redo leave a text field to the browser's own undo. After an undo or a redo, the addresses of the selection that no longer exist are dropped.

### The inspector

The inspector drawer opens from the `«` tab at the canvas's right edge and closes with its `»` button; the browser remembers whether it was open. It also opens when the first editor opens on the canvas, and it may be closed while an editor is open. It shows the block the whole selection lies in. Below its heading it has a WAI-ARIA tab list of up to four tabs: Editor, present only while an editor is open, then Properties, Manifest and Journal, always present. Properties is selected when the page opens and Editor whenever an editor opens; leaving the last editor while Editor is selected selects Properties. Otherwise the chosen tab is kept while the selection changes, and it is not remembered across reloads. With no block selected, and no unapplied text, the Properties and Manifest tabs show only the hint "Select a block to inspect its manifest." On a focused tab the Left and Right arrows move to the previous and the next present tab, wrapping around, and Home and End to the first and the last; moving selects the tab. With Alt, Ctrl or Meta held, these keys are left to the browser.

- **The editing bar.** While an editor is open, a bar above the tabs (a group named "Editing") holds a green **Done** button, a red **Cancel** button, the text "Editing:" and the editing path, a list named "Editing path" of the open editors' names joined by " > ", outermost first: a bundle's `name`, else its `id`, else "Anonymous bundle", and a group's or timeline's `name`, else its id. Done closes the innermost editor, and so does a double-click outside the edited element. Cancel closes it at once when its session holds no change to discard; otherwise a modal dialog beside the button asks "Are you sure you want to discard 1 change?" (or "n changes?"), with Yes and No, No focused; No, Escape and a click outside the dialog keep the editor open, and Yes cancels it. The count is the store's `changes`. While the drawer is closed, Escape on the canvas still gives Done, and Cancel waits until the drawer is opened again.
- **Editor.** The Editor tab names the innermost editor, "Bundle editor: `<name>`", "Group editor: `<name>`" or "Timeline editor: `<name>`", and holds nothing else yet.
- **Journal.** The Journal tab lists the journal of the level shown, one row per entry, each with its time (`HH:MM:SS`, UTC), its author and a text: "Added `<kind>` `<id>` to `<into>`", "Set `<properties>` of `<target>`" (with " and N more" for further changes of the same command), "Removed `<targets>`", "Styled `<selector>`", and for a closed session "Edited `<kind>` `<name>` (n changes)" while its target exists, else "Edited `<address>` (n changes)", the target's full address with no kind word. Rows run newest first. On the arranger it lists the main journal, each session one row; in an editor, the entries of its session, followed by the read-only rows of the earlier session of the same element when one is listed ([The store and its journal](#the-store-and-its-journal)), greyed below a heavier rule. A session's row counts its changes at every depth and has a disclosure button that lists its entries, newest first, the sessions among them expandable in turn; which rows are expanded is the panel's own state, never stored. A session partly undone reads "Edited `<kind>` `<name>` (n changes, k undone)". Undone entries stay listed at the top, at every depth, grey and half transparent and marked "undone" for screen readers (a session's row once all its changes are undone), until they are redone or a new command replaces them; they are not saved.

- **The inspected thing.** Beside its Inspector heading, outside the tabs, the inspector names whatever is selected, by its kind and its name, or its id when it has no name: "Bundle `<name>`", or "Anonymous bundle" for a bundle with neither; "Group `<name>`"; "Timeline `<name>`"; a timeline's card as "Card of timeline `<name>`"; a part by the element it belongs to, as "Start of timeline `<name>`" or "Title of bundle `<name>`"; and a region, a conversion map, a break, a jump or a marker by its own kind in the same way, as "Region `<name>`". A selection of several things is named "N selected".
- **Properties.** The Properties tab holds a form for the geometry of what is selected, never the block's when something inside it is: a block's `x`, `y`, `scale`, `length`, `spacing`, `width` and `height`; a group's frame or an ungrouped root's card, selected by the frame or card, by the timeline's line or any part of it, or for a frame by its title, the `x`, `y`, `scale`, `length`, `spacing`, `width` and `height` of its place; a group member's card, selected the same way, its group's `scale` and `length`, labelled "group scale" and "group length" since all members share them, and its own card's `spacing`, `width` and `height`. A field shows the stated value, else the drawn one. Several selected elements of one kind are edited together, one `set` for all; a field whose values differ stays empty with the placeholder "mixed", and a step moves each element from its own value. A selection of different kinds, or of an element without a box of its own, shows the hint "Select a block, a frame or a card to edit its geometry." Each field shows its value rounded to at most two decimals; the stored value keeps every digit until a new one is committed. Typed text is applied as one `set` on Enter or when the field loses the focus, and Escape discards it; an empty `width` or `height` is `null` for a block, the content's own size, and unstates the member in a place. An edit of a place follows its level's rule for gestures: on the arranger and in the bundle editor its `set` also states the drawn `x` and `y` of every other item that states none, the frame holding an edited member's card excepted, so that no other item moves; in the group and timeline editors it states only the places it changes. A `length` or `spacing`, typed or stepped, writes what a Stretch to that value writes (`stretchChanges`): every stated width (for a `length`) or height (for a `spacing`) of the frame or card and of the cards it holds, or for a member card's `spacing` of the card and its frame, keeps its proportion to its content; in the group editor a `length` on the frame or on a member's card stays within the frame, which keeps its width, exactly as a Stretch there does. A step, with a spin button, the Up and Down arrow keys or a wheel turn over the focused field, is applied at once as one `set` of its own: it adds or subtracts 1 for `x`, `y`, `length`, `width` and `height` and 0.1 for `scale` and `spacing`, starting from the exact value, never from the rounded text (from the typed text when there is some; an empty field counts as 0). The result is the exact decimal one: 1 − 0.1 gives 0.9, and 0.2 + 0.1 gives 0.3 rather than the binary sum 0.30000000000000004. While a block, or a frame or card in it, is dragged or resized, the fields follow the gesture, showing what the canvas previews for whatever is selected in that block; the store changes only on release, and the fields then show the stored values. Text being typed is never replaced. A refused value is shown beside its field. In a group or timeline editor the block's `scale`, `length` and `spacing` fields are disabled, since changing them there is a side effect ([No side effects](#no-side-effects)); a frame's or an ungrouped card's `x` and `y` are disabled everywhere but in the bundle editor, the one level that moves items.
- **Locked.** When the selection is exactly one timeline, or one part of a timeline such as its card, a plain checkbox labelled "Locked" in the property form, after `height`, or, for a child timeline drawn in no card of its own, as the form's only cell, shows the timeline's own `locked`; any other selection shows none. Locking and unlocking is not available yet, so the checkbox is disabled and greyed out for every timeline. A plain segment always shows it unchecked, since a segment is never locked ([Locking](#invariants)).
- **The manifest as text.** The Manifest tab holds, in this order, the format, the Include styling and Minimal checkboxes, the text, Apply and Revert, the problems and the warnings. The text is the manifest in JSON (timeskeleton's standard writer), YAML or TOML, chosen by three radio buttons; YAML ([decisions/0024](../decisions/0024-yaml-library.md)) and TOML ([decisions/0025](../decisions/0025-toml-library.md)) are loaded the first time they are chosen. Numbers stay exact in all three: integers of any size, and integral floats, which the text writes as `2.0`. Apply, or Ctrl+Enter (Cmd+Enter) in the text, reads the text and dispatches one `set` replacing the block's manifest; the store's checks decide. A text that stands for the stored manifest, compared in its complete form, dispatches nothing. A refused text stays as typed, and its problems are listed: a syntax error at its line and column, any other problem at the JSON pointer of its member in the manifest. While the same block stays selected, an applied YAML or TOML text is patched in place rather than rewritten, so comments typed into it are kept, with Minimal checked or not. After an accepted Apply the text shows the stored manifest, and so do the Locked checkbox and the inspected name; property text typed but not committed is discarded, and the selected tab stays as it is.
- **Apply and Revert.** Both buttons are enabled exactly while the text differs from the text shown, by as little as one character. They are disabled again whenever the two are equal: when the shown text is typed back character for character, after Revert, and after an accepted Apply. Revert shows the stored manifest again, the newer one when it changed meanwhile. A refused Apply keeps the text and its problems, so both buttons stay enabled. A text that is equal to the shown text again always follows the stored manifest: it shows a manifest that changed meanwhile and drops the notice, and the problems of a refused Apply go with the refused text, while a problem of writing the manifest, such as a null that TOML cannot hold, stays listed. Ctrl+Enter (Cmd+Enter) applies only while the text holds an edit. These rules hold in every format, with styling included or excluded, and with Minimal checked or not.
- **Unapplied edits.** While the text holds an edit, the format, Include styling and Minimal cannot be changed, and a hint says "Apply or Revert to switch". A change of the manifest from elsewhere (a gesture, an undo), or of the selection, does not replace the text, and Apply still applies it to the block it was written for; a notice says that the manifest changed, and Revert shows the selected block's manifest, or only the hint when no block is selected. An unapplied text survives a visit to the Properties tab.
- **Include styling.** Unchecked, as it is by default, it leaves the manifest's `graphical` block out of the text; applying a text then keeps the block's styling as it is, and a `graphical` member typed into the text is refused rather than dropped, with "the styling is excluded; check Include styling to edit graphical". Checked, the text shows `graphical` and applying it replaces the styling as well.
- **Minimal.** Unchecked, as it is by default, the text shows the manifest in the complete form; checked, it shows the minimal form, every key whose value is its default left out, after Include styling has left out `graphical` or not. The editor stores every manifest in the complete form, so a minimal text is read in its complete form when it is applied.
- **Warnings.** The keys of the selected block's manifest that the schema does not declare (timeskeleton's `unknownKeys`) are listed in the Manifest tab after the problems, each as "Unknown key `<key>` at `<pointer>`", or "at the top level" for a key of the manifest itself. They are warnings: a misspelt optional key would otherwise silently become its default. They disable nothing, follow the stored manifest rather than unapplied text, and the keys themselves are kept and written back.
- **TOML and null.** TOML has no null. A member that may be null and that the schema either requires or gives the default `null` is left out of the TOML text when it is null and read back as null when it is missing, so a read gives back the complete form; in schema 0.7.0 these are `length`, `name`, `measure_map` and `metric_hierarchy` of a timeline, `name`, `source_unit` and `target_unit` of a conversion map, `name` of a region and of a marker, `name` and `label` of a break, `target` and `label` of a jump, and `name` of a group and of the manifest. They are found by walking the one schema document along the value. A manifest holding any other null, such as a measure-map row's optional `nominal_length`, cannot be shown as TOML, and the inspector names that null's path.

## Exact values and commands

Exact rationals remain exact while positions are carried to the root timeline's axis. A coordinate is one atomic value, never a container of separately editable parts: on its timeline's own axis it is written as its value alone, and on another axis, as in a conversion map's tables, as `{ unit, number_type, value }`; either value is a JSON integer, a JSON number or a `[numerator, denominator]` Fraction pair as the axis's number type selects, following the BOPP core primitives. Layout converts a root-axis proportion to a double once and performs the remaining canvas arithmetic as binary64 in the order the drawing specification gives. The writers round the exact value of each resulting double to four decimal places, ties to even, when they serialize it. Canvas quantities of a block (position, scale, length, spacing, box size, places) are plain finite numbers: they place a drawing and carry no musical meaning.

Every edit is a serializable, validated command carrying its author and time. Commands are the single entry point for the UI, tests, and automation. Before applying an edit, command handling checks invariants such as containment, number type, and unit. The schema validates a manifest on load, on save, and whenever a command brings one into a block.

The workspace is a plain immutable value, changed only by applying a command. The store keeps every command it applies in a journal, which is saved in the workspace file beside the workspace it produced; the commands made in an editor form a session, kept as one entry of the journal. Replaying the journal reproduces the workspace, and the journal is also the undo history; undo steps through the commands one at a time, into a session's commands as well. Event tables remain outside the manifest and move as Arrow data rather than being embedded in TimeSkeleton.

## The core package

`@timetoalign/tilie-core` is framework-free: no DOM, no Svelte, no network. Its one entry point holds the numbers, the manifest types, the manifest's structure (`rootPaths`, `memberDrawings`, `isNamed`, `elementAddress`, `elementOf`, `TITLE_ADDRESS`, `PART_WORDS`), `loadManifest`, `saveManifest` and `checkManifest`, Delete (`removedBy`, `withoutElements`, and for a segment `isSegment`, `segmentGaps`, `withoutSegment`, `movedBy`), the workspace view and blocks with their places and band orders, ids and order keys, `parseCommand` and `apply`, the store and `replay` with the editors' sessions (`editorKindOf`, `mintSessionId`, `isSessionEntry`), the side-effect guard (`contains`, `sideEffect`), `readWorkspace` and `writeWorkspace`, and the error types. The package needs Node 22.18 or later, as `@timetoalign/timeskeleton` does.

### Numbers

`Rational` is an exact fraction over `BigInt`, always normalized (positive denominator, lowest terms), with exact addition, subtraction, multiplication, division and `floor`. It is built from a `[numerator, denominator]` pair, a `bigint`, a safe integer or a decimal integer string, and never from a JavaScript float: `0.5` and `2 ** 53` are refused. A `Real` is a value as Python's numeric tower holds it, an exact `Rational` or a float; `addReal` and `compareReal` combine and compare such values as the tower does (a sum involving a float is a float, a comparison is exact), and `realOf` reads a coordinate's value as one. `fromFloat` returns the exact binary value of a float, as Python's `Fraction(float)` does, and `toFloat` the double nearest to a `Rational`; `fromFloat` serves arithmetic that must be exact on a float's value, such as the writers' page transform, and never re-expresses a coordinate. A `Coordinate` is `{unit, numberType, value}` whose value is what the axis's number type declares: a `bigint` for `int`, a `number` for `float`, a `Rational` for `fraction`. A value on its timeline's own axis is bare: `readAxisValue` and `axisCoordinate` read it and `toAxisValue` writes it, as timetoalign's `number_from_json` and `number_to_json` do: an `int` axis reads a JSON integer, or an integral JSON number as that integer; a `float` axis reads a JSON number, or an integer as the float it equals exactly; a `fraction` axis reads only a pair; every integer is int64-bounded. Arithmetic and comparison (`addCoordinates`, `subtractCoordinates`, `compareCoordinates`, `coordinatesEqual`) work within one axis only, and throw `AxisMismatchError` across units or number types.

### The manifest value

A manifest held by `core` is always in the complete form: the value `@timetoalign/timeskeleton`'s `parse` returns for a valid 0.7.0 manifest, passed through its `complete`, so every key with a default is present. It is typed member by member on the schema package's generated types: `Manifest` is `{timeskeleton, $schema?, id?, name, meta, timelines, groups, graphical?}`, and every timeline in it is a `TimelineManifest`, whose `length` is a value or `null` and whose `children` is an array of timelines, each with its `offset`. A value on a timeline's own axis (`length`, `offset`, region `start` and `end`, break and marker `coordinate`, jump `from_coordinate` and `to_coordinate`) is bare (`AxisValue`): a JSON integer, a JSON number or a `[numerator, denominator]` pair, as the axis's number type selects. There is no file kind. `manifest.timelines` holds the root timelines, `rootPaths` gives each with its path in the manifest, and `memberDrawings` lists what the drawing draws as roots: each group's members in display order, each with its ancestors, then the ungrouped roots. A key the schema does not declare is kept where it was found: values are spread, never rebuilt from known fields, so unknown keys survive every command and are written back. Every number in it is a `JsonNumber`: a plain `number` for a safe integer or a float with a fractional part, a `bigint` for an integer beyond 2^53, and a `JsonFloat` for an integral float, so that `600.0` stays a float and is written back as `600.0`. A command that carries a float whose value is an integer passes it as a `JsonFloat`. `core` reads, orders and writes no JSON of its own: reading, the canonical order and the standard writer, which sorts every object's keys by code point, are the schema package's.

### Load and save

`loadManifest(text)` reads the text with `parseJson` and validates it with timeskeleton's `validate`, which reads the version marker first: a value without `timeskeleton` is not a manifest, and one declaring another version than 0.7.0 is refused at `["timeskeleton"]`; there is no migration. It then completes the manifest with `complete`, puts it in canonical order and checks every invariant, root by root. A manifest that reaches core any other way, in a workspace file or a command, is read the same way. It returns the manifest, or a `LoadError` whose `problems` list `invalid_json` for text that is not JSON, the first `schema_violation` with the path the shared validator reports, or every invariant violation of a schema-valid manifest; unknown keys are never problems. `saveManifest(manifest, {minimal?})` validates the manifest and checks its invariants, throwing `InvalidManifestError` with every problem, and writes it with the schema package's `dumps` in the complete form, or, with `minimal: true`, in the minimal form: canonical order, the standard text, byte-identical to what the Python writer produces. Every 0.7.0 manifest fixture of the schema package loads and saves to its own bytes, and its minimal twin loads to the same manifest and saves, asked for the minimal form, to the twin's bytes.

### Commands

Every edit is a command, a plain JSON object `{type, ...}`, and there are four: `add`, `set`, `remove` and `style`. Each is aimed at addresses, and the kind of its target decides what it does. `apply(view, command)` is a pure reducer: it never modifies its input and returns either the new view or a `CommandError` `{code, message, path}`.

- `add {into, <kind>: value}` adds a `block` into `workspace`, or a `child`, `region`, `break`, `jump`, `marker` or `map` into a timeline's address. The value carries its id; a child is completed before it is placed.
- `set {changes: [{target, values: {...properties}}]}` sets properties of blocks and elements; the properties are nested under `values`, so none of them (such as a jump's `target`) collides with the change's `target`. One gesture is one command, so moving five blocks is one `set` with five changes.
- `remove {targets}` removes blocks and elements, mixed, every target resolved before anything is removed; a block goes with every block whose `parent` chain reaches it. A removed timeline, root or child, takes along its subtree; its id from every group's `members` and from `graphical.order`; every conversion map whose `source_id` or `target_id` names a removed timeline; and every entry of a style statement's `ids` that addresses a removed element, a statement left with none going too. A group left without members stays. A removed group goes alone: its members stay in the manifest, roots ungrouped and children in their parents, and its display order and the `ids` entries addressing it go with it. Removing the last root leaves the manifest with no timeline, drawn as an empty box. A removed timeline also takes every style statement whose `select.within` names it. A segment that would leave a gap in its segment line is refused with `gap_required` unless the command carries `gap {side, verb}` (`left` or `right`, `extend` or `shift`, as [Selection, marquee and deletion](#selection-marquee-and-deletion) describes them); a command with a `gap` has exactly one target, which must be a segment (`wrong_target_kind` otherwise), and a way that is not permitted is refused with `gap_not_permitted`. The canvas sends no `gap` yet, because it refuses the Delete of a segment itself.
- `style {select, set, name?, blocks?}` puts a style statement into the manifest of each listed block, or of every block with an element the selector matches when none is listed. With `name`, the declaration becomes a named style in that manifest's `styles`. A statement whose selector equals an existing one is merged into it; a property set to `null` is removed, and a statement left empty is dropped.

What each target admits:

| Target | Address | `set` | `add` into it | `remove` |
| --- | --- | --- | --- | --- |
| workspace | `workspace` | `grid {size, snap}`, `blockDefaults {scale, length, spacing, width, height, order}`, `graphical` (the default statements) | `block` | no |
| block | `<block>` | `x`, `y`, `index`, `scale`, `length`, `spacing`, `width`, `height`, `order`, `manifest` (whole) | none | yes |
| timeline (root or child) | `<block>/<id>` | `name`, `length` (a value, or `null` for not known), `locked`, `meta`, `band_order`; a child also `offset`; an ungrouped root also `place`, and a group's member, root or child, a `place` of only `width`, `height` and `spacing`, its card's size and vertical stretch | `child`, `region`, `break`, `jump`, `marker`, `map` | yes |
| group | `<block>/<id>` | `order` (its display order), `place`, `band_order` | none | yes |
| region | `<block>/<root>/<id>` | `name`, `start`, `end`, `meta` | none | yes |
| break | `<block>/<root>/<id>` | `coordinate`, `control_type`, `condition`, `repeat_count`, `label`, `name`, `meta` | none | yes |
| jump | `<block>/<root>/<id>` | `from_coordinate`, `to_coordinate`, `control_type`, `condition`, `repeat_count`, `label`, `meta`, and `target` (a marker id of the same timeline, or `null`) | none | yes |
| marker | `<block>/<root>/<id>` | `name`, `coordinate` | none | yes |
| conversion map | `<block>/<root>/<id>` | `map` (the payload, whole, its `id` unchanged) | none | yes |

Three properties arrange a block's drawing. A group's `order` is its display order, every member once, written to `graphical.order` of the block's manifest, or `null` to delete that entry (`invalid_order` "order must list every member of `<G>` once" otherwise). `place` merges into the block's `places` entry of a group or of an ungrouped root, the items of its drawing, or of a group's member, root or child, whose card takes only `width`, `height` and `spacing`: a member given a value is stated, a member given `null` is no longer stated, and a place left empty is deleted; a group's member given `x`, `y`, `length` or `scale` is refused with `not_an_item` at that member ("`<T>` is a member: its card takes only width, height and spacing"), and a timeline that is neither an item nor a member, one holding a member, with `not_an_item` ("`<T>` is not drawn in a card of its own"). `band_order` sets the band order of a group or a timeline at any depth, or deletes it with `null`. A command never fails for a stale key: after every command, each touched block drops the `places` keys that name neither an item nor a member, cuts a member's entry to its `width`, `height` and `spacing`, and drops the `bands` keys that no longer name a group or a timeline, as when a group is removed or a root becomes a member.

In every manifest a timeline and a group keep their bare address `<block>/<id>`, and a region, break, jump, marker or conversion map is addressed as `<block>/<root>/<id>`, `<root>` being the root timeline whose tree holds it. The manifest's own `id` names no target, and a root's `offset` cannot be set by command.

A command is atomic: one refused change refuses it whole. Ids are never settable. A timeline's `unit` and `number_type`, its `measure_map` and its `metric_hierarchy` are not settable. Canvas numbers are doubles; a position on an element's own axis is a bare value, normalized as its axis's number type selects: an integer on a `float` axis is stored as that float, an integer on a `fraction` axis or a coordinate dict is refused with `invalid_coordinate`, and a pair is reduced to lowest terms. The three ways of resizing a drawing are gestures that set different block properties, not commands. The caller mints the id of what it adds, so that replaying a journal is deterministic: a block id as described below, an element id with `nextId(view, block, prefix, into?)`, the smallest `{prefix}_{N}` that no id of the tree it goes into (the tree holding the timeline `into`) uses, and for a new timeline also no timeline id of the manifest, no group id and not the manifest's id; a map, region, break, jump or marker may carry a group's id, the manifest's id or an id of another tree, as the manifest's id scopes allow. An id already held in that scope is refused with `duplicate_id`.

`parseCommand(value)` reads a command from any value, as a user interface or an agent sends it, and `dispatch` and `apply` read every command through it. A refusal's path starts with the address of the target at fault, followed by the property or kind at fault (`[<address>, "length"]`), or by `"manifest"` and a location in the manifest the command would leave; only a malformed command, which has no target, names the malformed member of the command itself. The codes are stable strings, exported as `ErrorCode`:

- reading: `invalid_json`, `invalid_command`, `invalid_coordinate`, `invalid_value`, `schema_violation`;
- the workspace file: `unsupported_format`, `unsupported_version`, `unknown_member`, `missing_member`, `unknown_session`, `unreferenced_session`, `session_referenced_twice`;
- the workspace: `invalid_block_id`, `key_mismatch` (a block stored under another key), `unknown_parent`, `parent_cycle`, `invalid_index`, `duplicate_index`, `non_finite_number`, `non_positive_number`, `invalid_order`, `unknown_place`, `unknown_band_key`;
- addressing: `invalid_address`, `unknown_target`, `unknown_property`, `wrong_target_kind`, `id_not_settable`, `not_removable` (only `workspace` is not removable), `duplicate_id`, `not_an_item`;
- editors: `no_editor`, `not_inside`, `side_effect`;
- lengths and Delete, refused by a command: `child_exceeds_parent`, `locked`, `length_below_content`, `segment_end_fixed`, `gap_required`, `gap_not_permitted`;
- locks, refused by a command: `segment_never_locked`, `unlocking_not_supported`;
- manifest invariants: `number_type_not_allowed`, `region_end_before_start`, `map_source_unit_mismatch`, `metric_hierarchy_without_measure_map`, `negative_child_offset`.

### Invariants

The manifest invariants are timetoalign's, checked twice: by `checkManifest` over a loaded manifest and by every command over the manifest it would leave. The unit decides a timeline's class, and a unit admits its number types; every value on a timeline's own axis reads as that axis's number type; a region does not end before it starts; a map's source unit is the timeline's unit; a metric hierarchy needs a measure map. Every root's tree is checked in turn. That ids are unique in their scope (the manifest for timelines, groups and the manifest's id, the root's tree for every other element), whatever the kinds of the elements carrying them, that a jump's `target` names a marker of its timeline, that a child has its parent's unit and lies within its parent's known length, and that a segment line's segments are contiguous, are timeskeleton's rules, checked by its validator together with the schema; names are for display and may repeat. A negative child offset, a child starting before its parent's 0, is valid in the schema but not supported yet: core refuses it itself, on loading, in `checkManifest` and in every command, with `negative_child_offset` at the child's `offset` and the message `A negative child offset is not supported yet: child '<id>' has offset <offset>.`; a root's offset may be negative. The rules for a length belong to the commands that change one, which refuse at their own path before the manifest they would leave is checked. The catalogue in `app/packages/core/tests/README.md` lists every row.

**Locking.** `locked` states whether a timeline's length is fixed; it defaults to `false` on every timeline, and a child's `locked` is read and written as it stands, so a child may be unlocked. A segment is never locked: its segment line's lock governs it, so reading a manifest unlocks every segment, whatever the file states, and a segment is written with `false`. A segment line that is a child, a segment or a group member is locked: an `add` of a child gives every timeline of the added subtree the lock of its place, and such a line is written with an explicit `true`, in the minimal form too, since the default stays `false`. A file stating otherwise is kept as it is read; lifting that lock is not supported yet. A `locked` that contradicts its place is refused, at `[<address>, "locked"]` for a `set` and at `[<into>, "child"]` for an `add`: `true` on a plain segment with `segment_never_locked` ("A segment is never locked: lock its segment line '<id>' instead."), and `false` on a segment line that is a child, a segment or a group member with `unlocking_not_supported` ("Unlocking a segment line that is a child, a segment or a group member is not supported yet."). A `set` to the value the timeline already has changes nothing and is accepted, even where the opposite value would be refused. A locked timeline's length cannot be set (`locked`), whatever it is. The length of an unlocked timeline, root or child, may be set, never below the farthest point a child reaches (`length_below_content`), and a length change never pushes a parent: the new end stays within the parent's known length, whether the parent is locked or not, or the `set` is refused with `child_exceeds_parent` at `[<address>, "length"]`. A segment line fixes ends: a segment ends where its successor starts, and the last one where the line ends while the line's length is known; a segment line ends where its last segment ends while that segment's length is known. A length that would move such an end is refused with `segment_end_fixed`; a length of `null` is always taken. A child added into an unlocked timeline, or moved within one, past that timeline's known end grows that timeline to the child's end, and only that timeline: when the grown length would pass the timeline's own parent's known length or move a segment's end, the command is refused, with `child_exceeds_parent` at `[<into>, "child"]` for an `add` or at `[<address>, "offset"]` for a move, or with `segment_end_fixed`; a locked timeline refuses the child with `child_exceeds_parent`. timetoalign follows the same rule: a parent never grows because a child grew.

**Unknown length.** A `length` of `null` means that the length is not known, on any timeline: a root, a child, a segment, a locked timeline or a group member. It is a fact the manifest states, never inferred and never a violation; adding content leaves it unknown, and setting a length to or from `null` is an ordinary `set` (refused only on a locked timeline). Every check that needs an end runs where the end is known and is skipped where it is not: a child's offset lies at or before its parent's end when the parent's length is known, and the child ends within its parent when both lengths are known (timeskeleton's validator checks both). A child of unknown length reaches its offset, so adding it past the end of an unlocked timeline of known length grows that timeline to the offset; a timeline of unknown length stays unknown.

Two rules go beyond what the library enforces, because the editor addresses and stores values directly and refuses a manifest the library would not have written: a value on a timeline's own axis must already carry the axis's number type (the library would re-express it), and a parent grows only to a value its own number type holds exactly (an `int` parent cannot grow to 9/2, a `float` parent cannot grow to 1/3). What the library does not enforce, `core` does not invent: a region, break, jump or marker may lie outside its timeline, and any number of breaks or jumps may share a coordinate.

A child shares its parent's unit but may have another number type. Its end, offset plus length, and every comparison against it follow Python's numeric tower: an `int` and a Fraction are exact, a sum with a float is a float with each exact operand correctly rounded first, and a float compares with an exact value exactly.

### The workspace view

A workspace is held as a `View`, an immutable plain value: `meta` (`format: "tilie-workspace"`, `version: 3`), `settings` and `blocks`, a map from block id to block. The settings are `grid {size, snap}`, `blockDefaults` (scale 1, length 400, spacing 1, no requested box size, the band order `children`, `regions`, `flow`) and `graphical`, the workspace's default style statements, empty by default; the grid is 8 units with snapping.

A block has an `id`; a `parent`, the canvas group holding it, `null` in this version and never a timeline group, which lives in a manifest; an `index`, its order key among the blocks of the same parent; and exactly the inputs of its drawing besides the manifest's own: `x` and `y`, the canvas position of its drawing's place origin, `scale`, `length`, `spacing`, `width` and `height` (each `null` for the content's own size), `order` (a `BandOrder`, a permutation of `children`, `regions` and `flow`), `places`, `bands` and `manifest`. `places` maps the id of a group or of an ungrouped root (a root that no group names and that holds no member) to its stated place, an object of at least one of `x` and `y` (finite) and `length`, `scale`, `spacing`, `width` and `height` (positive), never `null`, and the id of a group's member to its card's stated `width`, `height` and `spacing`, any of them; `bands` maps the id of a group or of a timeline at any depth to its band order. Both are empty by default; they are the drawing's `places` and `bands` (timeskeleton's drawing specification, sections 1 and 8.6). `checkWorkspace(view)` returns every problem of a view, by block id: a block stored under another key, a malformed id, a missing parent, a cycle of parents, a malformed order key or one shared with a sibling, a canvas number that is not finite, a block scale, length, spacing, width or height that is not positive, a band order that is not a permutation of the three groups, a malformed place, a key of `places` that names no item and no member (`unknown_place`), a member's entry in `places` stating more than `width`, `height` and `spacing` (`unknown_member`), a key of `bands` that names no group and no timeline (`unknown_band_key`), and every schema or invariant problem of a block's manifest.

### Ids, addresses and order

A block id is ten characters from `0-9a-z`, drawn from the platform's cryptographic random source, rejecting bytes that would bias the alphabet. Block ids are the workspace's namespace. An address is `workspace`, a block id, or a block id followed by `/` and the address of an element of that block's manifest (`elementAddress`). One rule holds in every manifest: a timeline and a group keep their bare ids, and every other element is addressed as `<root>/<id>`, `<root>` being the root timeline whose tree holds it, also in a manifest of one root and also when a member below that root is drawn as a root of its own. A drawn part of an element appends `/start` or `/end` (the root's wedges, a member's marks on its ancestor lines, a segment's boundary at `/start`), `/name`, `/label` or `/card` to the element's address, as timeskeleton's drawing specification addresses it in the descriptors; these words are reserved, so no id of a manifest is one of them and `elementOf` reads every address without ambiguity. The manifest's title is addressed `name` (`TITLE_ADDRESS`), whether or not the manifest has an `id`, so naming a manifest changes no address; a group's title is `<group>/name`. A block id holds no `/`, so the first `/` splits an address (`parseAddress`, `formatAddress`); `mintBlockId()` draws a block id and `manifestIds(manifest)` lists the address of every element of a manifest. Element ids live inside a manifest, unique in their scope there and freely repeated across blocks; the id a manifest carries is the id, and `nextId` mints `{prefix}_{N}` (`clt_1`, `region_1`, `break_2`) only for an element that has none, following timetoalign's scheme.

Sibling order is a fractional index: a string key that compares with ordinary string comparison, so that a block moves between two others by taking a key between theirs, without renumbering. `indexBetween(a, b)` returns one key strictly between two keys (`null` for an open end), `indicesBetween(a, b, n)` returns `n` increasing keys, and `isIndex(key)` validates one. Keys are compatible with those of Rocicorp's `fractional-indexing` 4.0.0, written in `core` ([decisions/0016](../decisions/0016-fractional-indexing.md)).

### The store and its journal

`createStore(workspace, {author?, clock?})` holds a workspace, `{view, journal, sessions}`, and returns `view`, `journal`, `sessions`, `editing`, `entries`, `listed`, `changes`, `canUndo`, `canRedo`, `dispatch(command)`, `undo()`, `redo()`, `open(target)`, `done()`, `cancel()`, `snapshot()`, `setAuthor(name)` and `subscribe(listener)`, which returns a function that unsubscribes. `dispatch` stamps the command with its author (by default `Gerhardt`) and its time (ISO 8601, UTC, from the injected clock), applies it with the pure `apply`, and appends the entry `{command, author, time}`; it returns `null`, or the `CommandError` of a refused command, which leaves the store unchanged. The journal is the undo history, one change at a time, a change being one command at any depth: `undo` reverts the latest applied change (inside a closed session when that is where it lies), `redo` re-applies the earliest undone one, and a new command discards the undone changes; a partly undone session keeps its id and its applied changes. `replay(journal, sessions)` applies a journal from the empty workspace, expanding every session in place, and returns the view after each of its entries; the last has the workspace's settings and blocks, so undo reaches back across the loaded file. Views are kept per change with structural sharing, and an undo past the views the store holds applies the changes once from the latest view it does hold, or from the empty workspace at the start of a loaded journal. The store's decision record is [decisions/0019](../decisions/0019-workspace-store-and-journal.md).

**Editor sessions.** Every editor is a **session**: the commands made in it between its opening and Done or Cancel. The store keeps one level per open editor above the main journal, and the open editors are `editing`, outermost first, each `{session, target, kind, earlier}`: its session id (ten characters from `0-9a-z`, as a block id), its target (a block id, `<block>/<group>` or `<block>/<timeline>`) and its kind (`bundle`, `group` or `timeline`, from `editorKindOf`; any other address has `no_editor`). `entries` (the entries holding an applied change) and `listed` (every entry with how many of its changes are applied, a session's entries nested) are the innermost level's, the main journal's when no editor is open, and `dispatch`, `undo` and `redo` act on that level only: undo inside a session stops at its start, and undo reaches into a closed session on that level, reverting its changes one at a time, latest first.

- `open(target)` opens an editor; with one open, the target must lie inside the innermost target and not be it (`not_inside`). When the last entry holding an applied change on the level it opens on is the session of the same target, that session is **unfolded**: it is taken off the level and keeps its id; its applied changes are undoable again and its undone changes can be redone in the editor. Otherwise a fresh session opens, and `earlier` names the last session of the same target on that level, listed read only in the Journal tab; undo never reaches into it.
- `done()` closes the innermost editor. A session holding entries is stored under its id in `sessions`, and the entry `{session, author, time}`, stamped at Done, is appended to the level below, whose undone changes are discarded; a session left without entries records nothing.
- `cancel()` closes the innermost editor and restores exactly the state at its opening: the view, the level below (with an unfolded session put back) and `sessions`.
- `changes` counts what Cancel would discard: with `o` the changes applied at opening, flattened at every depth (none for a fresh session), `c` those now and `p` the length of their common prefix, `(o − p) + (c − p)`, and 0 with no editor open. The inspector asks before a Cancel exactly when it is positive.
- `snapshot()` returns the workspace as Save writes it, every open editor folded innermost first as Done would fold it, without closing anything, writing only applied changes (a partly undone session with its applied ones, a wholly undone one not at all), and with only the sessions its journal reaches.

`subscribe`'s listener is called after every change of the view, of a level's entries or undo state, and of the editing path.

### No side effects

An editor changes only what it edits. While an editor is open, `dispatch` checks the view a command would leave against the view before it with `sideEffect(before, after, target)`, the innermost editor's target, and refuses the command with `side_effect` ("`<what>` lies outside `<target>`: an editor changes only what it edits") at the path of the first difference that lies outside, in this order: a workspace setting; another block, added, removed or changed; for a group or timeline editor, its block's `scale`, `length`, `spacing`, `order`, `index` or `parent`; a key of the block's `places` or `bands` that the target does not contain, except that a member's editor may change its group's `length`, `scale`, `width` and `height` and the `width` of every sibling's card (the members share the length and scale, and a stretch keeps the frame's stated width and height and every card's stated width in proportion to their content); and the manifest outside the target, compared with the target's own object (and, for a group, each member's) reduced to its id, the group's `name`, `meta` and display order dropped, and only the style statements that match an element outside the target kept, with the named styles they use. A block's `x`, `y`, `width` and `height` are the container adapting and never a side effect, and removing or renaming the edited element is refused at the target. The bundle editor contains its whole block, so only the first two checks apply to it, and the removal of its own block is refused at the block.

What a target contains is `contains(manifest, container, element)`: a timeline contains itself, everything that belongs to it or to a descendant, and their parts (its card, wedges, names and labels), but no ancestor line; a group contains itself, its title and whatever its members contain; nothing else contains anything.

### The workspace file

A workspace is saved as one JSON file, `<name>.tle.json`: `{meta, settings, blocks, journal, sessions}`, with every manifest embedded whole. It holds the blocks, never the canvas engine's own state, so a text diff of two files shows only real changes. `writeWorkspace(workspace)` writes a `Workspace`, `{view, journal, sessions}`, with timeskeleton's standard writer `dumps`, which sorts the keys of every object by code point; Save and the autosave write `writeWorkspace(store.snapshot())`, so open editors are saved folded. A journal entry is exactly `{command, author, time}` or `{session, author, time}`, and a session exactly `{target, entries}`, its entries of the same two shapes, so sessions nest; a session holds at least one entry, and one without entries is refused with `invalid_value`. Every session is reached exactly once from the journal: an entry naming no session is refused with `unknown_session`, a session reached from nowhere (or only from a cycle) with `unreferenced_session`, and one reached twice with `session_referenced_twice`. `readWorkspace(text)` reads the file with timeskeleton's lossless `parseJson` and returns the `Workspace` or a `LoadError` listing every problem; a file of another `format` (`unsupported_format`) or another `version` (`unsupported_version`, such as "workspace version 2 is not supported; this editor reads version 3 only") is refused for that alone, before anything else in it is read; otherwise it refuses any unknown or missing member, any malformed block, place, band order, journal entry or session, and any manifest that fails the schema or an invariant, at its path in the file. This is version 3 of the format, whose blocks carry `places` and `bands` and whose journal holds sessions; there is no migration code, so a file of an earlier version is refused. `writeWorkspace(readWorkspace(text))` returns the text it read, byte for byte. `core` is the one implementation of the format; other programs read the file as plain JSON, and a block's manifest is a TimeSkeleton manifest that timetoalign reads with `AlignmentBundle.from_dict` whatever it holds, or with `Timeline.from_dict` or `TimelineGroup.from_dict` when it holds one root or one group.

### Autosave

The `editor` package keeps the last text of each workspace in the browser's IndexedDB, one slot per workspace key ([decisions/0018](../decisions/0018-indexeddb-autosave.md)). The editor uses one slot, whichever workspace is open: every change is written one second after the last, and a pending write is made at once when the page is hidden or the editor goes away. When the editor opens and the slot holds anything but an empty new workspace, it asks "Restore the unsaved workspace from …?", with the time of the workspace's last journal entry; Restore opens it, untitled and marked unsaved, and Discard empties the slot. A failing autosave is reported once, in a message, and editing goes on. `createAutosave({key, delayMs})` returns `schedule(text)`, which writes the text once no further text was scheduled for `delayMs`, and `flush()`, which writes the pending text now and waits for every write; `recoverWorkspace(key)` returns the last written text or `null`, and `clear(key)` empties a slot. The autosave stores the text `writeWorkspace` returns and never parses it. A storage failure reaches the caller as a promise rejected with an `AutosaveError` whose `code` is `indexeddb_unavailable` or `indexeddb_failed`.

## The schema contract

`@timetoalign/timeskeleton` supplies the types generated from its one schema document, the validator of the current schema version only, `unknownKeys`, `complete` and `minimal`, the canonical order and the standard writer, the manifest fixtures with their minimal twins, the rejection and warning cases, the drawing font and font metrics. It migrates nothing, and neither does TiLiE. The schema repository, not TiLiE, is the source of truth. Every application package takes schema 0.7.0 through a `link:` dependency on the `js/` package of a timeskeleton checkout lying beside this repository (`../timeskeleton/js` from its root), built there with `pnpm install` and `pnpm build`. The `timetoalign` library proves conformance in its own tests. TiLiE consumes that contract, preserving exact values and invoking validation at the manifest boundaries.

## Layout and writers

The drawing of a manifest is specified in the schema repository, not here: timeskeleton's [drawing specification](https://github.com/TimeToAlign/timeskeleton/blob/main/docs/drawing.md) defines the `graphical` block, arithmetic, default styles, font, layout, element descriptors, page, and SVG and TikZ profiles completely enough that another implementation writes the same text byte for byte. The specification, together with the SVG and TikZ fixtures of a schema version, pins the drawing. A drawing is derived and is not exchanged as JSON; there is no drawing schema.

`@timetoalign/tilie-layout` exports `draw(manifest, placement, layers, metrics)`, a pure deterministic function implementing sections 1 to 8 of the specification for every manifest. The placement supplies the graphical length of every item without one of its own, the vertical spacing, the requested box size, the band order with the band orders of groups and timelines that override it (`bandOrderOf`: a member drawing's root takes its own id's, else that of the group whose frame holds it, else the block's), and the places of the items. The layers are the ordered `Graphical` blocks of the cascade, from lowest to highest precedence: the specification's defaults, the workspace settings' `graphical`, and the manifest's own `graphical`; nothing lies above the manifest. The metrics are the advance widths of the bundled drawing font. The returned `Drawing` contains its box size, the box-local position `origin` of the place origin `(Ox, Oy)`, its `items` (each frame and ungrouped card in drawing order with its key, its kind, its address, its place with the defaults applied, its scale and spacing included and its drawn size before the scale, and its place as `places` states it), its `cards` (each member's card in drawing order with the member's id, its group, its address, its drawn size before the group's scale, its own vertical stretch `spacing`, and the `width`, `height` and `spacing` `places` states for it), its elements in descriptor order, and the code points measured with the font's fallback advance. Layout measures text, places bands and rows, and produces box-local canvas coordinates; it knows nothing about the drawing's position on a page.

The source is flat, one module per step of the specification. `draw` (`box.ts`) takes the member drawings core's `memberDrawings` lists, gives every item its place, stated or default, and the box its place origin, finds the box's one horizontal layout over all its items (the name column, the start and the right margin), lays each item out in its own coordinates and draws it at its place and scale, and places the manifest's title at the box's top left corner, the frames with their titles, and the cards with their shadows; every position is computed from the place origin and shifted into the box last. A member drawing (`member.ts`) is one timeline taken as the root: `traversal.ts` walks its timelines, fixes its axis (the length, or the reach when the length is `null`, from `numbers.ts`'s `reachOf`) and gives each timeline its end, known or open, `sides.ts` fills each side outwards in bands, the root band (`root.ts`: the line, its map stack and its wedges) first, then children (`children.ts`), regions (`regions.ts`) and flow control (`flow.ts`) in the root's band order, and above, last, the ancestor band (`ancestors.ts`: the ancestor lines, their chevrons and the member's marks). `segments.ts` draws a segment line's boundaries and labels, `maps.ts` the map stacks, `names.ts` the name column and the centred labels, `fit.ts` the first fit into rows, `heights.ts` a member drawing's heights and `canvas.ts` the distances, canvas positions, an item drawn at its place and scale, and the final shift into the box; `constants.ts`, `numbers.ts`, `metrics.ts`, `defaults.ts`, `cascade.ts` and `elements.ts` hold the constants, the arithmetic, text measurement, the default layer, the cascade and the drawing's types.

The style cascade is represented by `Cascade`, `INITIAL_STYLE`, and `DEFAULT_LAYER`. Each statement selects elements by the members of its `select` object and sets a declaration directly or through a name in the same layer's `styles`. The layer order and the statement rank defined by the specification decide each property independently; inherited properties fall through the element tree, and initial values fill the rest. The cascade runs on each drawing of an element at its own place in that tree, so the two drawings of a timeline drawn as an ancestor line and as a member differ only in the chain of elements holding them, which the selector member `inside` tests. `display: none` removes an element from both the drawing and its layout.

`@timetoalign/tilie-writers` exports `toDescriptors(drawing)`, `writeSvg(placed)` and `writeTikz(placed, options)`. `toDescriptors` returns the ordered SVG-shaped descriptors that an on-screen renderer and both writers share. `placed` is a list of `{drawing, x, y, scale}` values. The writers find the bounding box of all placed drawings, add a margin of 16 on every side, translate each drawing to the page, and apply its uniform scale. Frames, cards and card shadows are written as rounded `rect` elements and the chevrons of an open end (three) or of an ancestor line that runs on (two) as `polyline` elements; the TikZ writer draws the same shapes. `writeSvg` returns one SVG page. `writeTikz` returns a complete LuaLaTeX document by default; `standalone: false` returns the `tikzpicture` environment alone, and `fontDirectory` names the directory containing `DejaVuSans.ttf`. Both writers round the exact value of every double to four decimal places, ties to even, and neither depends on the on-screen renderer.

`pnpm -C app/packages/writers review`, run from the repository root, draws every manifest fixture of the installed schema version (not the minimal twins) except those taken from corpora (`corpus_*`), and the additional resize, style, place and band-order cases, then writes SVG and PNG files plus `index.html` under `app/packages/writers/review/`. The same 62 cases are timeskeleton's 0.7.0 drawing fixtures, which `emit-drawings` writes into a timeskeleton checkout, among them stated places, item scales and spacings, member card sizes and band orders at block and timeline level; twenty-two of their SVG figures are derived by hand from the specification, are never rewritten, and equal the writer's output byte for byte. It rasterizes the SVG files at twice their size with `rsvg-convert --zoom 2`. A temporary fontconfig configuration exposes only timeskeleton's bundled `DejaVuSans.ttf`; the command refuses to render if another font is visible or the rasterizer fails. This review workflow is recorded in [the rasterizer decision](../decisions/0017-rsvg-convert-for-review-renders.md).

The canvas memoizes the drawing per block ([One node per block](#one-node-per-block)). The review command rasterizes writer output for inspection; the application does not expose PNG, JPG, PDF, or `.drawio` export.

## The server

`tilie-server` uses FastAPI and uvicorn. It binds only `127.0.0.1`, generates a random token for each run, rejects foreign Host and Origin headers, and requires `Authorization: Bearer <token>` on every `/api/` route. `tilie` hands the token to the browser in the URL fragment (`http://127.0.0.1:<port>/#token=<token>`). A browser never sends the fragment to the server, so the token does not appear in the access log; the editor reads it, removes it from the address bar and the current history entry with `history.replaceState`, and keeps it in memory only, so reloading the page after the handoff loses the token. Every response carries `Referrer-Policy: no-referrer`, so the browser sends none of the server's URLs to another site. The current server serves the built app from its wheel and implements `/api/health`; `tilie` selects a free port and opens the browser, while `tilie --check` verifies an installation.

The server is intended to load any supported source through `timetoalign` loaders; run conversion-map batches; report unfolding and traversal diagnostics with fix suggestions; validate; export; host a committed OpenAPI document and generated TypeScript client; and proxy a GitHub token. These responsibilities are not exposed by the current API.

## Packages and the dependency ladder

The TypeScript workspace is a one-way ladder enforced by [dependency-cruiser](../app/.dependency-cruiser.cjs). Lower packages never import higher packages. Only the UI packages may import Svelte.

| Package | Intended contents | Workspace dependencies |
| --- | --- | --- |
| `@timetoalign/tilie-core` | The workspace view, blocks, ids and order keys; the manifest value of the one shape with its load, save in the complete or minimal form, invariants, element addresses and Delete; the commands, the store with its editor sessions, the side-effect guard and the workspace file; rationals and coordinates; framework-free. | None |
| `@timetoalign/tilie-layout` | `draw` with its box of frames and cards, member drawings and bands, drawing types, the style cascade, defaults, and font measurement. | core |
| `@timetoalign/tilie-writers` | Element descriptors, page placement, and SVG and TikZ writers over drawings. | layout, core |
| `@timetoalign/tilie-arranger` | The canvas: the projection of a workspace onto Svelte Flow nodes, the block node rendering the writers' descriptors with its hover marks, the gestures as commands, and the editors. The only package importing `@xyflow/svelte`. | writers, layout, core |
| `@timetoalign/tilie-client` | OpenAPI client and Arrow helpers. | core |
| `@timetoalign/tilie-editor` | The Svelte application: the header with the File menu and the offline mark, the canvas area, files, the inspector with its editing bar and its Editor and Journal tabs, the About dialog and its notices, and the autosave. | all workspace packages |

Packages for views and embedding are added only when a concrete need appears. `client` has a minimal export, and the ladder keeps `core` free of the browser.

## Testing and quality

Tests are README-first: every `tests/README.md` states the validation logic, and tests follow it. Expected values are exact. Fixtures flow from Python to TypeScript so both sides work from the same examples: `core` loads and saves every 0.7.0 manifest fixture of the schema package byte for byte (36 manifests directly under `fixtures/0.7.0/`, 10 under `groups/` and 9 under `bundles/`), loads each minimal twin to its fixture and writes it back in either form, and refuses every shared rejection at its pinned path. The places, band orders and display orders, the editor sessions (opening, the reopen rule, Done, Cancel and its count, nesting, undo one change at a time through nested sessions, the snapshot and the file's sessions) and the side-effect guard are tested case by case with exact expected values. Property tests with fast-check run generated command sequences from every 0.7.0 manifest fixture, and check that accepted commands keep the workspace and every block's manifest valid, that refused ones leave the view unchanged, that undo and redo restore every intermediate view, that Cancel restores exactly the state at its editor's opening, that replaying the journal equals the snapshot, that every journal entry carries its author and the injected clock's time, and that a workspace file reads and writes back to its own bytes. Budgets bound reading and writing a 300-block workspace with a 1,000-entry journal (250 ms each) and dispatching one command (1 ms); the store's decision record holds the figures, 10,000 blocks included. `layout` tests derive exact expected drawings from the drawing specification and cover defaults, the cascade, text metrics, side placement, map stacks and end markers, stretch, requested box size, the box with its frames and cards, places, the box's one horizontal layout, item scales, member card sizes, the vertical stretch of items and cards, the place origin and the band-order cascade, segment lines, ancestor lines, timelines of unknown length, and representative fixtures. Writer tests derive descriptors and serialized text from the same specification, check multi-drawing page placement and number formatting, require the twenty-two hand-derived figures to equal the writer's output byte for byte, and the bundles at their default inputs to equal the drawings of the box laid out once over all its items, parse every review SVG as XML, and compile every review TikZ document under LuaLaTeX with the bundled font. `arranger` tests derive the projection, snapping, the resize values of every mode and handle, the gesture commands, the Delete preview, the refusal of a selected title and of a segment's Delete, and the box or element a pointer target maps to, with what a press on it selects and what is hover-marked, and in the editors the target a double-click opens, the gestures of each level, item moves and resizes (the `RESIZING` table, every kind of box in every mode), member reordering, the focus viewport, the marquee and the drawing a gesture inside a block previews, from the drawing specification by hand; fast-check properties check that a projection of an unchanged view returns the identical node objects, that every gesture yields a command the store accepts, that a horizontal Stretch on a member's card outside the group editor sets only its group's `length` and `width` and its members' card widths and is accepted at that level, that a stretch never finds a longer length or spacing for a shorter pointer travel, that a stretch back to where it began never moves further away and, on a box that states no size, restores the length or spacing exactly, and that undo restores every placement exactly. A component test renders the block node for every drawing fixture of the schema package and compares its element tree with the fixture's SVG.

The canvas itself is tested end to end with Playwright in Chromium, Firefox and WebKit and on an emulated touch screen ([decisions/0021](../decisions/0021-playwright.md)): opening, dragging with snapping and guides, the lock, panning, the selection rectangle, clicks, deletion, order, keyboard moves, undo and redo by keys, resizing in every mode, culling counts at 300 and 900 blocks, and touch drag, pinch and taps; and so is the editor around it: saving, reopening and saving again byte for byte through the fallback file path, a refused file, the About dialog and its notices file, and an inspector edit applied, refused and undone, its form following a drag, a resize and a frame's Stretch in the bundle editor live, a resize cancelled with Escape, a step by key, spin button or wheel applied as one command, and the form editing a selected frame's and card's places, never the block's, with a frame's `x` and `y` disabled on the arranger; the editors: entering by double-click, Enter and a double tap, the viewport there and back, leaving by a double-click or a double tap outside the edited element, the view centred again when the drawer closes and opens, the faded surroundings, a click on the empty pane clearing the selection, nesting, Done, Cancel and its question, Escape, an item move, a reorder, a frame scaled on the arranger, a member's card stretching its group in its timeline editor, a refused side effect, three nested sessions undone one change at a time, and the Journal tab; a click on the empty canvas whose pointer moves slightly still clears the selection. Group and bundle blocks are tested for what they draw, for selecting an element drawn twice, for Delete in a group block and for hover. Expected values come from the store, read through a test hook, never from pixels. The hook, `window.__tilie` (`load`, `store`, `selection`, `select`, `viewport`, `setViewport`, `locked`, `mode`, `health`, `text`, `editing`, `open`, `done`, and `cancel`, which does not ask first), exists only in development builds and in builds made with `VITE_TILIE_TEST_HOOK=1`. The same builds show a Fixture menu in the editor's header, listing the end-to-end workspaces of `app/e2e/fixtures/` (among them `groups`, which holds four of the schema package's group fixtures, `group_child_member`, `group_grandchild`, `group_parents_mixed` and `group_styled`, and `bundles`, which holds its three bundle fixtures not taken from a corpus) and one workspace per group and bundle fixture of the schema package not taken from a corpus, built from the manifest fixture when it is first chosen, with a Load button that opens the chosen one, so a person can try the canvas on prepared workspaces. A production build, and so the wheel, contains neither the hook nor the menu nor the fixture files. The workspaces the suite opens are written by a generator script through the store's commands from the schema package's manifest fixtures, never by hand. axe-core checks the page for accessibility violations ([decisions/0022](../decisions/0022-axe-core.md)). Outside the pinned Playwright container image, `e2e/run.ts` runs the suite inside it through rootless podman, with `app/` mounted at its own path; a schema package linked from a sibling checkout lies outside `app/`, so it is mounted too, read-only at its own absolute path, where the links in `node_modules` find it (`e2e/container.ts`). Screenshots of the block nodes, the `groups` workspace among them, are compared with zero tolerance, only inside that image, where their baselines are made. Current gates include Biome, Vitest, fast-check, dependency-cruiser, svelte-check, Playwright, axe-core, LuaLaTeX, Ruff, and pytest.

The editor shell test covers the token handoff through the fragment and the absent token; it does not currently cover its CSS grid layout, mobile rendering, or a fragment carrying an empty token. The server static-file tests do not currently cover traversal behavior. These limits are documented coverage gaps rather than claims of behavior.

## Performance

A drag costs script time on every pointer move in proportion to the total number of nodes, culled or not, because Svelte Flow re-adopts its whole node list on each move. Measured in headless Chromium: about 1.2 ms per move at 100 blocks, 2.4 ms at 300 and 5 ms at 900. Culling reduces what is mounted (42 of 300 nodes in a zoomed view) but adds its own cost to pan and zoom (3.1 ms per wheel event at 300 blocks with culling against 0.4 ms without), so it starts above 500 blocks. One node per block, a complete projection, reused node objects and memoized drawings keep a gesture from doing any work of TiLiE's own until it ends.

The budgets, for a workspace of 300 blocks in Chromium, are checked by `pnpm e2e:budget` from the DevTools Protocol's script time: dragging a block at most 3 ms of script per pointer move; panning and wheel zoom at most 1 ms per move or event; one command at most 1 ms; one block's re-drawing within one frame (16.7 ms). Heavy data is intended to stay out of the DOM, in WebGL panes and columnar tables, with parsing that could block interaction in workers; server calls do not occur for every keystroke.

## Automation

The command layer (`parseCommand` and `apply` over a workspace view) and the server's OpenAPI document are the intended contracts for programmatic use. An MCP server and a command channel for live sessions are reserved for a future addition. At present, the only API route is the protected health endpoint.

## Dependencies and ADRs

Each dependency requires an ADR under [`decisions/`](../decisions/). The records use MADR headings, weigh writing the component ourselves, record maintenance and exit costs, name audited versions, and include review dates. Package manifests (`package.json`, `pyproject.toml`) declare compatible ranges for runtime and peer dependencies, such as `fastapi>=0.141,<1` in the server and `svelte` `^5.57.1` in `editor`; development dependencies, the npm `devDependencies` and the server's `dev` group, are pinned exactly. Lockfiles pin every resolved version: `server/uv.lock` for Python and `app/pnpm-lock.yaml` for the application. A version must have been released at least 14 days before it enters a lockfile, and the ADR identifies the audited version. The one exception to that window is this project's own schema package, `@timetoalign/timeskeleton` (`minimumReleaseAgeExclude` in `app/pnpm-workspace.yaml`), so that a schema release can be consumed as soon as it is published. The same package is also the one exception to compatible ranges: while TiLiE is built against a schema version that is not yet released, as it is now against schema 0.7.0, the packages that use it (`core`, `layout`, `writers`, `arranger` and `editor`) depend on it through a committed `link:` to the built `js/` directory of a timeskeleton checkout beside this repository (`../timeskeleton/js`), and the repository is not published in that state; once the version is released, the `link:` is replaced by a compatible range from npm (`^0.7.0`). This policy deliberately separates compatibility declarations from reproducible resolutions.

## Deployment

Install the current product with `pip install tilie-server`, then run `tilie`. The installed wheel contains the built browser app, so starting it does not require Node.js or a runtime download.

The deployment model is intended to grow toward a hosted browser app that communicates with a user-run local server, a desktop wrapper, and collaborative hosting. Those deployment forms are not available today.
